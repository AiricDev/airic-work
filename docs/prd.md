# Airic Work 产品定义

Airic Work 是一个通过 API 使用的 **OM Worker**。调用方提交任务指令，由 Airic Work 固定部署配置中的 Operating Model（OM），可按任务附带资料和工具连接。Worker 按固定版本的 OM 工作，遇到需要人判断的问题时创建 Decision Request，在收到回答后继续受影响的工作。任务、问题、回答、续行和结果都可通过 API 核查。

Decision Request 是产品的核心。一次人工介入应该有明确的问题、依据、影响范围和后续去向。人可以在合适的时候集中处理问题，Agent 可以先推进独立工作。事后可以沿着记录检查哪些介入是必要的，哪些反映了方法或执行上的不足。

本文定义目标产品。现有镜像、前端和 OpenAPI 描述的是先前版本，见文末的实现参考。

## 目标与使用者

| 使用者 | 要完成的工作 | 可观察的价值 |
| --- | --- | --- |
| 委托方与集成开发者 | 用一次请求启动工作，查询进展、回答问题并获取结果 | 可脱离业务前端完成联调，接入另一种工作主要改变 OM 和任务配置 |
| 作答人 | 理解 Agent 需要什么判断、提交回应、确认工作是否接续 | 可从问题详情直接作答，无需翻查整段轨迹或在另一套工作台处理 |
| OM 维护者 | 根据实际提问、人工回答和后续结果发现方法改进点 | 能定位当时的 OM 版本与实际依据，并用同一案例重跑验证 |

产品交付面是 HTTP API 和 OpenAPI。Swagger UI 可以作为通用测试客户端。业务应用自行提供业务工作台，负责业务对象、业务权限和正式结果。OM 的编写、评审和发布在外部完成。Airic Work 的领域依赖只有随任务指定的 OM。模型、沙箱和存储是运行基础设施，业务 MCP 是每个任务可选的连接。独立部署只需配置 Worker 的运行环境与 API 访问，无需配置 CertLab 登录、会话交接或业务专用连接。

## 核心场景

1. **独立运行。** 测试者通过 Swagger UI 提交一个文档核查任务，附上固定 OM 和材料，不配置 MCP。Agent 发现一个例外需要人工判断，提出问题并继续检查其他材料。测试者查到问题和依据，提交回应，再查看同一 Task 的续行与结果。
2. **业务系统接入。** CertLab 在报告页提交任务，带上报告引用和已授权的 MCP 连接。工程师在 CertLab 内回答问题，CertLab 通过 API 读写 Airic Work 的 Decision Request。Agent 用原会话继续，按业务授权保存草稿并留下回执。测试者也可以预先取得同类 MCP 连接，直接用 Swagger UI 跑这一场景，无需打开 CertLab 网页。
3. **离线与恢复。** 作答人提交回答后可以离开。即使 Worker 当时不可用，API 也能确认回答已保存。Worker 恢复后从原 Task 的相关上下文接续。OM 维护者可以回看问题、回答与后续工作，再用新版本 OM 创建一个独立 Task 做对照。

## 对象与归属

| 对象 | 含义和归属 |
| --- | --- |
| **Task** | 一次交给 Airic Work 的工作委托，是公开 API、查询和持久数据归属的主对象。拥有稳定的 `task_id`，绑定任务指令、调用方和固定 OM。同一业务对象可有多个 Task。 |
| **Session** | 一个 Task 的持久 Agent 会话与可查询轨迹，保存消息、工具调用及返回、续行关联。一个 Task 对应一个 Session。内部可有多个上下文分支，暂停、恢复和补充输入沿用同一 Session。 |
| **Workspace** | 一个 Task 的文件空间。任务资料、工作文件和输出按权限提供给 Agent 或调用方。每个 Task 使用独立目录归拢运行数据，沙箱内仅开放该任务可访问的工作文件。 |
| **Decision Request** | Agent 在一个 Task 中针对具体问题提出的人工介入请求。可要求补充事实、给出专业判断、选择方案或明确授权范围。问题带有版本化的 Decision Context 和受影响的工作范围。 |
| **User Decision** | 对一个 Decision Request 的一次人工回答。保存原文、选择、提交人、时间、所回应的 Context 版本及可选附件。补充和更正追加历史。 |
| **Steering Input** | 提交给 Task 的一般补充指令或材料。可推进原工作，有独立的来源和投递记录。 |
| **Decision Episode** | 围绕一个 Decision Request 读取的问题、上下文修订、回答、投递和相关续行记录。以请求为入口查询，由已有记录组成。 |

公开接口用 **Task**。先前文档中的 **Execution** 对应这里的 Task。Session 专指 Agent 的会话与轨迹。项目、报告、工单等业务对象通过调用方提供的外部引用关联。业务应用维护这些对象的状态，也负责决定谁可以使用其界面发起任务或处理业务工作。Airic Work 校验自己的 API 调用身份及 Task 访问范围。

## 创建与运行 Task

### 一次请求描述任务

| 输入 | 要求 |
| --- | --- |
| 工作指令 | 必填。说明目标、范围、预期产出和约束。 |
| OM | 必填。提供可解析的来源、版本引用和入口。Worker 在执行前固定实际版本并记录来源。 |
| 任务上下文与资料 | 可选。接收结构化上下文、外部对象引用、已提交文件或可访问的资料引用。 |
| MCP 连接 | 可选。可配置零个或多个具名连接，每个连接给出端点和所需认证信息或凭据引用。连接随 Task 提交，无需先创建任务再完成业务系统登录交接。 |

调用方一次提交任务所需的运行描述。有效创建返回 Task ID、当前状态和固定 OM 版本，随后由 Worker 自动准备并执行。创建成功表示委托已保存。OM 版本无法解析、必要资料不可读、连接不可达或授权失效时，API 应返回可定位的阻碍、受影响的工作及可用的恢复方式。未配置 MCP 的任务可以使用 OM 与已有资料直接产出结果。任务配置可以使用宿主已授权的资源，模型与沙箱配置由运行环境提供。

例如，文档核查任务可以只提供「检查这份交付清单，列出缺项」和一个文件引用。CertLab 报告评估任务可以在同一次创建请求里提供评估指令、报告引用和已授权的 CertLab MCP 连接。两者使用同一个创建操作。

Airic Work API 身份与 MCP 认证分别校验。业务凭据由运行宿主保管，可用于原 Task 的后续调用。包含凭据的完整 MCP 链接整体按秘密处理。提示词、沙箱工作文件、查询响应、Session 和日志只保留可公开给相应调用方的连接标识或脱敏信息。

### 查询、继续和停止

- 调用方可以查询 Task 的当前状态、待回答事项、阻碍、产出引用和 Session。等待人工时说明哪些工作依赖哪些请求。状态应区分委托已保存、正在运行、等待人工、运行受阻与本轮已结束。业务产出仍以业务系统的权威记录和回执为准。
- Task 的原始委托、实际 OM 版本和来源可追溯。回答或补充输入可以在本轮结束后续行原 Task。更换 OM 版本用于新 Task。重启恢复保留原 Task、Session、工作文件和未交付输入。
- 取消接口分别呈现停止请求已接收和 Worker 已停止。停止后续工作不会撤销已有业务操作。外部工具操作结果未知时保留原调用身份，按该工具合同核对后再决定是否重试。
- 调用方可读取本地输出或业务产出引用，并核对相关工具调用与回执。记录区分调用发起、返回、失败和结果未知。能定位原始消息，并说明缺失或脱敏的范围。

## Decision Request 的 API 行为

### 提问与查看

- Agent 在 OM 所需的事实、判断或授权无法自行取得时发起请求。一个请求围绕一个可回应的问题，说明触发原因、已知依据及来源版本、缺口、可选方案和各自影响，以及依赖回答的工作。多个工作项共享同一个判断时，可以引用同一个请求。
- API 提供按 Task 查询全部请求、按授权范围查询待回答请求、查看单条详情及其 Decision Episode 的能力。列表提供摘要与状态，详情提供完整问题、Context 版本、依据引用、选项和后续影响。集成方可以用外部引用把待办带回业务页面。
- Agent 只让出受该问题影响的工作，仍可推进独立工作并提出其他请求。相关工作需要多个回答时，等自身依赖满足再继续。一个无关请求保持待回答，不阻止已经具备输入的工作续行。行为可通过顺序执行验证，内部调度策略由技术设计决定。

### 回答与续行

- 作答人逐条提交回应，可以选择、用文字回答或要求进一步调查，并按需提供附件或固定资料引用。回答关联实际查看的 Context 版本，保留提交人、内容、限制和来源。Context 有更新时，原版及原回答仍可查。Agent 依照当前证据和 OM 判断原回答的适用范围。
- 回答保存与待投递输入一并持久化。提交成功即表示该请求已回答。API 分别报告 **回答已保存、输入已交付、相关工作已续行**。交付或运行失败保留回答并提供可核查的状态。专业采纳和正式审批遵循业务规则。
- 每条回答路由回原 Task、原请求及对应工作，带上提问时的上下文。Agent 在写入业务系统前重新核对当前对象与版本。补充或更正保留原记录并关联被更正的回答。需要人作出新的判断时可以提出新请求，原请求保留已回答状态。
- 创建 Task 和提交回答支持幂等重试。同一身份对同一操作用原键重试相同内容，取回原结果；同键改内容返回冲突。Worker 恢复时也使用稳定身份识别已创建的请求和已接收的回答，避免产生重复提问、回答或输入。

## OpenAPI 交付范围

OpenAPI 是集成和验收入口，声明认证、请求字段、幂等键、响应、可见状态、分页和错误行为，并给出有 MCP 与无 MCP 的请求示例。下表定义公开能力，具体路径和 Schema 由接口设计定稿。

| 能力 | 仅用 API 能完成的操作 |
| --- | --- |
| Task | 创建、查询列表和详情、提交补充输入、请求停止 |
| Decision Request | 查询单个 Task 的请求、查询有权处理的待办、读取问题详情与历史 |
| User Decision | 回答、补充或更正，读取原始提交和投递、续行状态 |
| Session 与结果 | 查询会话、工具调用、已记录的业务回执和输出引用，按请求追溯相关续行 |
| 文件 | 提交任务或回答所需的文件，获取有权读取的输出 |

Airic Work 独立认证这些 API 请求，能够在测试环境中单独运行和验证。业务应用可选用这些 API 提供自己的用户入口。CertLab 作为集成示例只需提供常规业务 MCP 能力，Decision Request 的持久记录与交付由 Airic Work 负责。

## 核心验收

以下是目标验收条件，尚待实现和执行。手工验收可以用 Swagger UI，回归测试使用同一份 OpenAPI 合同调用服务。

| 场景 | 通过条件 |
| --- | --- |
| 无 MCP 的独立启动 | 使用一个固定 OM、资料和任务指令创建 Task。Worker 自动开始，API 能核对实际采用的 OM 版本、任务结果和 Session。无需部署或登录任何业务系统。 |
| 问题有足够上下文 | 只用 Decision Request 详情就能判断需要回答什么、依据是什么及哪些工作受影响。请求能追到固定 OM 与相关 Session 记录。 |
| 等待期间继续 | 对两段独立工作，Agent 在一处提出请求后仍推进另一处。两条独立请求先回答其中一条时，对应工作继续，另一条保持待回答。 |
| 提交与重启 | 保存回答后、投递前重启 Worker。同一键重试得到原回答，原 Session 只接收一次该输入，API 可区分已保存、已交付和已续行。 |
| 创建重试与停止 | 创建回执丢失时，用原键取回同一个 Task。请求停止后，API 能查到实际停止状态，以及此前已有的产出和业务回执。 |
| 更正与版本 | 能同时查到原回答、更正、各自回应的 Context 版本和后续记录。外部 OM 发布新版本后，原 Task 仍用原固定版本继续。 |
| 授权与凭据隔离 | 无权调用方不能读取或回答他人的请求。配置含凭据的 MCP 链接后，Task 查询、工具轨迹及错误响应均不返回凭据。 |
| 真实 MCP | 直接给一个有效的测试用 CertLab MCP 连接，在 Swagger UI 完成创建、提问、回答、续行和核对草稿回执。连接失效时可以从 API 定位受影响的工作。 |
| 对照复盘 | 从同一个请求追到原上下文、回答、续行和结果。用不同 OM 版本另建 Task，能分别核对两次工作所用的方法与产出。 |

## 产品价值验证

用代表性工作比较接入所需的部署步骤、调试时间、完成工作的人类投入和返工情况，并沿用业务原有的质量标准。抽查 Decision Request 能否由作答人直接处理，回答是否确实推进了相关工作。评估 OM 改进时，区分必要的人类判断、证据缺口、方法不足和运行故障。请求数量的变化要结合遗漏、成果质量和人工投入解释。
