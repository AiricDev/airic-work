# 保留原界面的真实接口接入

以既有 AppShell、pages/components 为唯一 UI；保留项目表格、执行双栏、Decision Brief、处理与核对步骤、OM 文件树和设置布局。

- 本人 API 记录才显示；加载、空和失败不注入 seed。
- UserDecision 支持选项、自由文本、附件；固定实际阅读修订，不预选、不强制编造理由。
- 提交未知后保留原 payload/key，刷新后仍可同键重试；不能编辑或另建命令。
- Context 更新不改写草稿依据；明确查看新版才变更阅读修订。
- 上传保存真实字节并取得 Upload ID；回答/Steering 引用 ID，不用 data URL 伪装 Workspace。
- 保存回答/消息与 Agent 接收/继续分开；取消显示 stopping，不能计时推断 stopped。
- 浏览指定固定 SHA，不可取得时提示，不回退其他修订。
- 登出/身份失效清空内存数据，草稿按用户隔离。
- 无合同的能力保留说明位置，不提供模拟成功。

边界：Application 拥有权限和写入；HTTP 负责认证/DTO；前端 API 负责传输与视图映射，既有 Context 负责查询和草稿，原组件实现交互。不伪造生产 Workspace 或调度。
验证：HTTP 权限/CSRF/幂等/文件，映射/草稿恢复/原路由依赖测试，以及原布局浏览器核对。

## 问题摘要与详情

- 给定 Agent 提供独立 summary 与多段 question，待决列表、执行内队列和简短关联只显示摘要，打开后完整正文按 Markdown 展示；无预选和逐项提交规则不变。
- 给定历史请求没有 summary，只生成显示用短标题，不修改原问题、Context 或回答依据。
- 打开请求后队列默认收起以展示详情，可随时展开切换；长执行指示默认两行，可查看完整指示。
- 结构化 Decision Context 按段落/列表展开，保留来源与版本；不执行原始 HTML，不自动请求远程图片。


## 单层 UserDecision 回应

- 候选方案与风险直接作为单选卡片，“需要进一步调查”为同级选择；默认无选择，移除“处理方式→方案”的二级操作。
- 统一补充框始终可用。没有方案选择时，文字/附件作为补充事实提交；有方案时保留 optionId 与可选文字，调查选择提交明确的调查回应，均不生成理由。
- 从方案切换到调查或仅补充内容时保留已输入文字，清除原方案关联；未知提交仍沿用原 payload/key，禁改正文，不重建命令。更正与 Context 阅读版本合同保持不变。
- 来源引用默认折叠。OM 文件链接包含来源 Commit 和执行引用；业务链接只能来自宿主配置的模板或引用中明确给出的 HTTP(S) 地址。缺失路由保留原始引用，不猜测跳转。

对应验证：`frontend/tests/decision-response.test.tsx` 的选项切换、空白/单选/纯文本、未知提交不变、单层表单及链接解析；页面交互另用现有隔离请求检查。
