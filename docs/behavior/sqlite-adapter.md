# SQLite / Support 行为验收

范围：ControlStore 与 Support；不运行 Agent，不实现 History、Workspace 或派发 worker。
业务语义沿用 `backend-phase1.md`，以下例子细化真实提交边界。

| 场景 | Given / When | Then |
| --- | --- | --- |
| S01 | 同 issuer/subject 或同分组由多个进程同时创建 | 身份/Project 唯一；重新接入不覆盖本地停用、权限或资料 |
| S02 | 同用户、操作、key 重复提交或更改 fingerprint | 同内容返回原结果，异内容冲突；当前资格仍须通过 |
| S03 | 已读取执行/配置，提交前配置被更新 | prepare 冲突，不固定 Method 或开始输入 |
| S04 | 回答提交的任意写入点失败或进程退出 | 回答、已回答状态、文件绑定、输入及幂等结果全有或全无 |
| S05 | Context 已刷新，使用旧版阅读修订回答并更正 | 旧版可回答；更正追加；首次 answeredAt、旧修订和原提交保持 |
| S06 | 同执行多个输入并发提交 | 序号持久、唯一、连续；重放不占用新序号 |
| S07 | 新输入与 Finish 竞争 | 输入先提交则 Finish 被阻止；Finish 先提交仍允许保存新输入 |
| S08 | 停用用户与提交并发、或管理员同时降级 | 当前资格/责任保护在事务内复查；不能移除最后有效管理员 |
| S09 | 跨用户/执行文件绑定或覆盖已固定 Upload | 提交被拒绝，不留下输入、回答或命令结果 |
| S10 | 旧执行版本/运行代次更新或取消中恢复 running | 冲突/阻塞，不改变归属、固定版本、Session 或 Workspace |
| S11 | 同 inputId 重复确认或更改 receipt | 相同确认安全；不同 receipt 冲突；不证明 Agent 已处理 |
| S12 | 提交后关闭并重新打开真实数据库 | 原记录、序号、幂等结果和接收凭据保留；迁移不重置设置 |

共享合同测试验证端口语义；SQLite 专用集成测试验证真实约束、事务、
独立连接/进程竞争和进程终止窗口。进程终止测试不等同于物理断电或磁盘硬件验证。
