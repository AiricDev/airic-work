# 第一阶段行为与实现计划

依据：PRD Ontology 和技术设计。范围为 Domain、Application、端口和测试替身；不接真实 HTTP/SQLite/Pi/Docker/MCP，不修改前端。当前没有后端架构索引，从设计中的能力表和用例顺序建立入口。

## 放置与修改闭包

* Domain：User、Project、Execution、DecisionRequest、UserDecision、Steering Input、固定文件及纯规则；不接 SDK/存储。
* Application：账户、执行、判断、输入交付、文件、方法、MCP、查询和设置用例；出口合同由用例拥有。
* 测试替身：以命名提交方法实现原子性、CAS、唯一约束和幂等，不能作为生产存储使用。
* 外部边界：Runtime 同一 Session 接收/去重、文件固定内容、Git 最新确认、身份 token 和 Session 历史必须由适配器后续证明。
* 已授权行为按 PRD 实现，不新增产品实体；首次管理员部署引导、Project 改名等未决产品问题不代为决定。

实现顺序：行为例子 → 纯领域不变量 → 用例及命名 Store 合同 → 内存替身 → 场景测试 → 类型与依赖检查 → 路由索引和交接报告。后续代理可实现端口机制，不得改变语义。

## 行为场景

| ID | Given / When | Then |
| --- | --- | --- |
| C01 | 集成用户首次/重复接入，或本地已停用再接入 | 唯一 User，默认启用，停用不被重置 |
| C02 | 相同分组并发创建；同键重试/异内容 | Project 唯一，创建幂等独立于 task.id；异内容冲突 |
| C03 | 新执行准备；Git 失败/配置修订变化 | 失败不固定旧版；成功固定 OM、Session、Workspace；重试不换版本 |
| C04 | Agent 创建 DecisionRequest，用户提交 UserDecision | 一一 Decision Episode；回答、已回答事实和消息同事务 |
| C05 | Context 已刷新、旧版本回答、更正及重复提交 | 旧版可回答；更正追加；同消息不重复；回答不依赖 Agent 采纳 |
| C06 | 消息落库后交付失败、Runtime 已接收后应用确认失败 | 回答仍成立；同 inputId 查回，重试不重复消息 |
| C07 | Execution 结束后新消息，或新消息与 Finish 竞争 | 同 Session/Workspace/OM 续行；待交付消息不丢失 |
| C08 | 取消在途、收到新消息、旧代次调用 | 新输入保留，停止确认前不续行；旧代次不能调用工具 |
| C09 | 文件未固定、越权绑定、物化失败 | 无错误绑定；已保存回答不撤销；文件失败可重试 |
| C10 | 其他用户或管理员读取执行、分页或命令缓存 | 均不继承归属内容权限，停用拒绝 |
| C11 | MCP 调用未能持久记录发起、网络超时、重复逻辑调用 | 未记录不发送；未知不重试；每次尝试可定位，不设业务账本 |
| C12 | 写操作筛选、未知分类、分类配置改变 | 保留当时分类，写筛选提示未知；不猜测判断关联或业务成功 |
| C13 | 唯一管理员降级/停用、本人停用、有责任用户停用 | 拒绝破坏性操作；不新增转派 |
| C14 | Session/Decision Episode/MCP 外部读取 | 同一用户查询规则；只读应用表面不暴露命令 |
| C15 | OM 浏览/搜索/读取 .ome 或越界路径 | 固定快照查询，拒绝作者区域及越界，Git 外部维护 |

以上为内层验收合同。并发、断电、容器与 SDK 真实恢复仍须在后续适配器集成验证，不以 fake-port 通过代替。
