# Files Blob 行为验收

范围：`Files.put` 的本地内容固定机制，以及现有上传用例与 SQLite 的衔接。
不新增应用读文件/下载合同，不实现 Workspace、物化、派发、清理策略或 Agent。

| 场景 | Given / When | Then |
| --- | --- | --- |
| F01 | 上传空内容、二进制或 Unicode 字节 | 保存逐字节一致的内容，返回实际 SHA-256、字节数与非路径内容引用 |
| F02 | 相同内容重复或并发上传 | 返回相同内容身份，正式内容不覆盖、不出现半文件 |
| F03 | 不同内容、相同显示名或跨用户上传相同内容 | 内容按摘要固定；Upload 的 ID、用户和执行范围独立，内容引用不授予访问权限 |
| F04 | 调用期间调用方修改原字节数组 | 保存本次调用获取的独立字节快照，哈希与实际内容一致 |
| F05 | 临时写入、同步或发布失败 | 不返回可用引用，不建立正式 Upload；尽力移除本次临时文件，不覆盖已有内容 |
| F06 | 内容已存在但损坏，或路径含异常文件/符号链接 | 拒绝伪造可用性，不覆盖损坏内容或跟随受管目录内的符号链接 |
| F07 | Blob 固定后数据库提交失败 | 没有正式 Upload，可能留下完整孤立 Blob；重试复用内容，不代替用户猜测清理时机 |
| F08 | 重新创建 adapter 或独立进程同时写入 | 原内容仍可核验，并发以文件系统原子发布仲裁，不依赖进程内 Map/锁 |
| F09 | 无权访问执行的用户请求上传 | 在 Blob 写入前拒绝；文件名不用于构造宿主路径 |

部署根目录由可信宿主配置，不能挂载给 Agent 或允许不可信进程写入。
验证范围为本地 POSIX 文件系统；进程并发/重开不等同于断电或硬件故障验证。
