# Airic Work 产品交互与原型设计方案

## Product Overview

Airic Work 是以 Operating Model（OM）驱动的后台执行与 Decision Request 协作平台。每个 Airic Work 实例仅配置并使用一个 OM 仓库（单一来源）；平台上的所有 Project 和 Execution 共用该实例配置的来源分支与仓库，不支持多 OM 列表、实例内选择器、按 Project 绑定不同 OM 或在执行时选择 OM。Execution 仍记录其实际使用的仓库来源和固定 Commit SHA，历史可追溯保持不变。

本方案以上传的 prd.md 为基础，结合本线程后续明确决定统一修订。本线程关于学习外置、OM 文件化管理和新增对外只读 MCP 的决定，覆盖原 PRD 的相应旧边界；上传文件本身未被修改。本文是设计规格，不代表功能已实现，不固定完整任务生命周期或正式接口。

### 产品范围

| 范围 | Airic Work 的职责 | 外部职责 | 工作 |
| --- | --- | --- | --- |
| Project、Execution、Decision Queue、Decision Context、执行询问与受控取消 | 业务系统管理业务大任务、业务事实与正式完成状态 | 知识展示 OM 文件、Git 提交历史、变更描述及文件差异；加载最新来源修订 | 执行专家与外部 Agent 编写 OM，GitHub/GitLab 管理分支、PR/MR、Review、审批与合并 |
| 实践记录 | 保存、关联、查询与展示 Trajectory、Decision Episode 及相关 Context 引用 | 外部环境开展 Reflection、归因、学习、方法验证和 OM 改进 | 管理单组织管理员直接创建、编辑、启停用户；系统配置、个人资料、偏好与身份关联 |
| 业务系统验证业务主体和实际业务权限 | 集成 | 标准任务/决策 API、出站业务 MCP、Git 获取、入站轨迹只读 MCP | 各系统按各自权威边界处理身份、数据与变更 |

Decision Context 是用户或 Agent 作出判断所依赖的信息及其依赖关系，包括业务事实和对象状态、规则与文档、既往决定、必要授权、来源版本，以及缺失或待更新的信息。重点是需要什么、来自哪里、是否可用且当前有效、缺失影响哪些判断，以及哪些工作仍可继续。证据属于 Context 的一部分，不等于全部；Decision Brief 是当前 Request 与 Context 面向人的组织呈现，不另建重复知识体系。

OM 对平台而言是一组 Git 文件。Decision 关系、Knowledge Gap、Precedent 和验证材料可以存在于文件内部，但不成为平台独立管理的语义对象、图谱、看板或审核流程。执行 Agent 理解文件，不等于平台建设 OM 语义治理产品。

新 Execution 在实际启动前获取所配置来源分支的最新可确认提交，记录具体 Commit SHA 后执行；启动后不因仓库变更静默切换版本。不能把旧缓存冒称最新。来源分支、同步时限和完整故障策略仍待详细设计；本轮原型遇到无法确认最新时阻止新执行进入实际运行，保留浏览历史的能力。

Airic Work 不设学习中心、反思分析任务、学习发现审阅或改进候选管理。Trajectory 和 Episode 仍由平台管理，外部 Agent 经授权通过只读 MCP 读取，再在外部分析和改进 OM，经 GitHub/GitLab Review 与合并后供未来执行使用。Episode 不自动成为正式 Precedent。

### 集成与权限原则

* 标准任务/决策 API：业务系统发起、查询、取消执行，查询和处理 Request；工作台共用服务及权威记录。
* 出站业务 MCP：后台 Agent 以任务归属人本人经验证且有效授权的业务身份读取、取证和操作业务系统，不回退到管理员、共享服务账号或其他用户。
* Git：获取 OM 文件、提交与差异；变更管理完全依赖 GitHub/GitLab。
* 入站轨迹 MCP：外部 Agent 在授权范围内查询/读取 Trajectory、Episode，以及理解记录所需的执行版本与 Context 引用。仅只读最小范围，不创建/取消执行、提交决定、修改 OM、重放业务操作或读取令牌。

平台保持 Project → 多个 Execution 的组织关系；任务只有一位归属人，不设计多人竞争处理 Request。业务系统是执行创建主入口，不增加通用手工新建执行表单。管理员维护平台用户与经验证的身份映射；本人授权与映射分离，管理员不能代本人同意或获得业务超级权限。

既有 prototype 仍含旧学习入口、OM 语义页面和简化交互，且未使用真实 MUI；这些不是本方案的目标能力。本次仅修订文档，不更新 prototype。

## Design & Visual Style

### 组件与主题

采用 @mui/material、@mui/icons-material、@emotion/react、@emotion/styled，通过 ThemeProvider、CssBaseline、createTheme 统一主题；布局采用 Box、Stack、Grid 和 sx。不混用 Tailwind、shadcn 或 Lucide。环境不能使用真实 MUI 时明确报告限制，不将视觉近似称为真实 MUI。

* 浅色主题，primary 使用 MUI 默认蓝，页面背景 grey.50，面板 background.paper，边界 divider，文字 text.primary/text.secondary。
* 沿用默认 typography、shape、焦点、禁用态与层级；字体 Roboto、Noto Sans SC、系统无衬线回退；ID/SHA 局部等宽。
* 页面标题 h5，执行与详情标题 h6，区段 subtitle1，正文 body2，长文 body1，元信息 caption。
* 默认 8px spacing；桌面页面 padding 3，窄屏 2，面板 3，区块 gap 2，元信息 gap 1。
* 内容 Paper 使用 outlined、elevation 0；Dialog 和 temporary Drawer 使用默认阴影。不使用渐变、玻璃拟态、巨型统计卡或装饰图谱。
* 列表使用 MUI Core Table 与 TablePagination，不引入付费 MUI X。紧凑表行最小约 56px，筛选用 size small TextField/Autocomplete。

### 布局与反馈

桌面基准 1440×900，AppBar 64px，常驻 Drawer 240px；移动 AppBar 56px。lg 及以上常驻导航，其余临时导航。执行详情空间允许时采用 Grid minmax(0,1.1fr) minmax(420px,1fr)，gap 2；小于 md 改为执行/待决 Tabs，不开发拖动分隔线。

Decision Context 详情 Drawer 桌面 640px、窄屏全宽。桌面执行面板分别滚动，操作区保持可见且不遮内容；移动使用单一页面滚动，Dialog fullScreen。表格仅容器内横滚。

| 情况 | 视觉反馈 | 行为 |
| --- | --- | --- |
| 进行中 | info outlined Chip | 使用具体工作描述，不编造百分比 |
| 需判断 | warning outlined Chip | 定位具体 Request |
| Agent 结束 | default outlined Chip | 单列业务完成状态边界 |
| 决定已记录 | 持久 success Alert | 等待实际后续事件 |
| Context/授权失效 | warning Alert | 保留输入，阻止无效操作 |
| 失败 | error Alert 与字段错误 | 局部重试，不清空成功区域 |
| 结果未知 | warning Alert | 查询同一操作，不盲目重放 |
| 同步失败/断连 | 最后同步时间与 warning Alert | 缓存不能伪装最新/实时 |
| 加载 | Skeleton | 保留布局结构 |

Snackbar 仅用于复制等短反馈；保存、决定和账户变更的结果持久可见。提交中禁用重复点击。采用 MUI 的键盘交互、模态焦点管理与可见焦点；关闭返回原触发点，颜色配文字，遵循减少动态效果偏好。

## Pages & Navigation

### 导航与路径

主导航：工作（项目、全部执行、待决事项）、知识（Operating Models）、管理（系统设置、用户管理，仅管理员）。Trajectory 从执行进入，Episode 从轨迹或稳定链接进入。底部头像菜单含个人设置、方法与接入指南、退出。

默认 / 跳转 /projects。除 /login 演示页外均要求会话；成员直接访问管理页面返回403，未知路径或不可定位对象有不泄漏信息的不可用/404说明。returnTo 仅允许站内路径。

### Project 与执行概览

Project 将多个 Execution 关联到业务系统的大任务对象，不承担权威业务状态、结果合并、调度或自动完成。原型假设一个 Execution 属于一个 Project，跨 Project 共享/迁移、Project负责人继承 TBD。

项目列表包含名称、来源及稳定业务引用、可见执行数、需我处理数、最近活动；非零待决用 warning Chip。项目工作区顶部 Breadcrumbs、标题、业务引用、返回业务系统按钮，简短统计文字和执行/待决 Tabs。全部执行增加 Project 列与筛选。

标题 Link 导航，待决数直达 Request；返回保留过滤与滚动。切换 Project 清除不匹配的请求/Context，不沿用另一用户缓存。空状态说明执行主要来自业务系统，无通用新建按钮。汇总仅基于授权可见记录，不泄漏不可见对象数量。

### 执行与 Decision Context

```text
项目 > 项目名 > 执行目标              [业务系统] [更多]
归属人 / 代表的业务身份 / 授权状态 / 实际OM SHA
┌─────────────────────────┬────────────────────────────┐
│ 正在进行 / 等待 / 可继续│ 待决 [待处理] [已处理]     │
│ [进展][结果][执行记录]  │ 问题、影响、Agent建议      │
│ 关键事件与阶段产物      │ Decision Context依赖列表  │
│ [查看完整Trajectory]   │ 事实/假设/缺失/方案风险    │
│ [询问执行情况 ▾]       │ 处理表单 [核对并提交]     │
└─────────────────────────┴────────────────────────────┘
```

顶部展示目标、Project、业务引用、唯一归属人、当前代表的业务账号与授权状态、实际 OM SHA、同步时间。身份 Drawer 区分技术调用方、实际发起用户、执行所代表的业务主体、Agent技术执行者和实际决策处理人。

左侧默认关键进展；结果区分已确认产物、草稿、效果未知；执行记录可进 Trajectory。普通询问解释已记录情况，不自动改变目标、范围、授权或创建 Resolution。后台不依赖聊天窗口在线。

右侧 Request 列表采用 ListItemButton selected。Brief 首屏说明问题、触发、影响、可继续部分与建议的不确定性。Context依赖列表展示信息名称、来源/版本、可用性、有效性与影响；点开 Drawer 阅读业务对象、文档、规则或既往处理记录。缺失事实与假设独立标识，不能用摘要冒充原文。

依赖以列表和关联引用表达，不新增复杂依赖图或通用知识管理。允许显示就绪、缺失、待核实、过期、无访问权等原型标签；这些不是完整生命周期。来源更新需要重新核对而非静默覆盖判断时的记录。

处理方式按具体请求允许的动作和本人权限展示：专业判断、事实补充、限定授权、进一步调查。不预选判断，不设计多人抢占或独立分派。切页/切请求保护草稿，草稿不等于正式决定。

### OM文件与Git历史

OM 列表不再作为多仓库选择界面：本实例面向单一仓库的页面顶部显示仓库、配置来源分支、最新确认 SHA 与同步状态/时间的摘要。主区域为文件目录、全文搜索与正文阅读，历史以 Tab 或链接进入；未配置仓库时显示未配置空状态并提示管理员前往 Git 设置，普通成员提示联系管理员。未同步或同步失败保留明确提示，不提供新建 OM 的入口。本实例配置为单一仓库与来源分支，不是仓库管理列表；在确认对应本实例仓库时，旧 /oms 链接可选择性重定向，否则显示不可用，且不恢复多仓库选择功能。

* 文件为只读 Markdown/文本；保留标题、表格、代码与相对链接，路径与 SHA 确定读取版本，拒绝越权或目录穿越。
* 主文件视图以本实例唯一配置仓库为上下文：顶部摘要显示仓库、配置分支、最新确认 SHA、同步时间/状态；主区域为文件目录、全文搜索与正文阅读，历史通过 Tab/链接查看提交历史与 diff。
* Decision、Knowledge Gap 和验证材料即使出现在正文，也不被拆成专门页面或数据管理对象。
* 提交历史展示 Git 原始提交描述、作者、时间与 SHA，不能把描述包装成已证明的改进成效；提交详情展示父提交、变更文件与 diff；二进制或不支持格式只显示文件元信息及 Git 跳转，不伪造预览。

### Trajectory与Decision Episode

Trajectory保存实际动作、观察、工具结果、人工处理与后续结果，不展示隐藏思考链。页面显示执行、OM/Runtime/Skill版本、覆盖时间和缺失记录提示；支持事件类型/时间范围/请求引用过滤与分页，不要求平台解析OM Decision关系。

事件详情包括经授权脱敏的输入输出、动作发起/结果确认程度、权威回执、业务主体、Agent技术执行者、Context来源版本及前后事件。原始事件只读，缺失/已清理/不可访问部分有明确限制。

Episode围绕一次实际判断展示当时的问题、Context依赖、所用文件修订、结论、人工干预与结果，关联原轨迹定位。它不等于学习结论或正式Precedent。可预览Episode引用供外部读取，不提供平台内开始反思、分析或采纳按钮。

### 外部只读MCP接入

指南提供只读范围说明、授权状态及轨迹/Episode稳定引用；系统设置配置服务侧策略，个人设置展示本人已授权的外部客户端及范围。MCP工具名、传输、认证协议和正式资源Schema为TBD，原型用明确的模拟读取面板，不伪造可用真实Endpoint。

允许的产品能力为按授权范围定位执行记录、分页读取轨迹、读取Episode及必要版本/Context引用。所有调用校验调用身份、客户端授权、对象访问与来源数据策略；外部读取既不继承Agent原执行权限，也不因知道记录ID而获得访问权。引用本身不赋予读取业务原文的权限。

原型可预览即将交付的虚构记录、脱敏字段和缺失限制，演示授权通过/拒绝并写读取审计。生产协议不以复制上下文包代替；默认不提供全量轨迹外发、令牌访问或业务写入能力。平台不接收外部学习发现作为内部流程对象。

外部专家通过该接口取得授权材料，在自己选择的Agent环境中使用OME方法分析、修改OM、验证，再经GitHub/GitLab提交和Review。平台只在后续同步取得新Git文件，不负责学习过程或审核。

### 系统设置

管理员页面采用二级List+最大约960px表单，每区独立保存/恢复；脏值离开提示保存/放弃/取消。技术测试、保存、实际生效分离，失败保留输入；变更不能静默改变运行中执行的身份、SHA或权限。

| 分区 | 内容 | 交互与边界 |
| --- | --- | --- |
| general | 组织显示名、默认时区 | 单组织，无租户切换/计费 |
| git | 托管平台、仓库、来源分支、凭据引用、同步记录 | 测试只读连通；同步文件/提交，不做语义索引；默认分支TBD |
| business | 系统及实例ID、名称、业务跳转、MCP Endpoint、身份来源及客户端配置引用 | 连接测试不代表本人授权或业务操作权限 |
| business的API说明 | 创建/查询/取消执行、查询/处理Request、可信身份来源、调用记录 | 不编造已发布接口或令牌发行协议 |

| runtime | Pi Durable目标、执行Skill版本、能力说明与验证记录、访问/资源边界 | 未验证标明；不装配后台反思或热切换既有执行 |

Git、业务MCP、标准API、只读轨迹MCP分开配置。禁用连接前展示运行依赖，影响不明时阻止操作，不借配置操作停止任务。真实凭据由服务端安全托管，只保存引用，不回显或写入浏览器、OM、提示词或轨迹。

### 用户管理与业务身份

管理员直接创建用户：显示名、唯一登录标识/邮箱、管理员或成员角色、初始有效/停用状态。校验格式和重复；无需成员接受，无自助注册、邀请邮件、链接或默认密码。登录初始化/SSO/重置机制TBD。

列表支持搜索、角色/状态筛选，展示账户状态与业务身份就绪情况，两者不能混为一谈。用户详情含账户、业务身份、管理记录与待交接责任引用。角色/启停操作确认影响，禁止自停用、停用/降级最后有效管理员；有未交接执行或待决责任时阻止停用，不增加转派流程。停用不删除历史，恢复不自动恢复外部业务授权。

管理员维护platformUserId到业务系统实例内externalSubjectId的映射。不能按同名或相同邮箱自动关联；手工输入仅待验证，经业务系统可验证依据确认后生效。本轮假设每用户每业务实例一个有效身份，同一外部身份不能映射多个平台用户；一个用户可关联不同业务系统。

管理员不能代本人同意、读取令牌或以管理员账号测试成员业务权限。变更映射先显示受影响执行；不能让运行中的执行静默换人，影响不确定则阻止，历史主体不改写。

### 个人设置与本人授权

资料：显示名可改，登录邮箱、组织和角色只读，首字母头像。偏好：语言（简体中文/English US）、IANA时区、待决新增/执行异常/执行结果更新的站内提示。显式保存/恢复，英文未实现需说明；通知已读不等于处理Request。不增加深色主题、邮件/短信或浏览器推送。

业务账号区展示关联系统/实例、业务账号、验证状态、授权状态、范围、有效期与最近校验；未知到期信息不猜测。本人可连接/重新授权、只读测试、撤销委托；不能任意替换管理员维护的映射。映射已验证不等于委托有效，委托有效不等于目标业务操作有权。

MCP代表Execution归属人本人操作。技术调用方、实际发起人、执行主体、Agent与决策处理人分别记录；业务系统请求不能自由填写userId冒用，调用方与归属人不同时需可验证合法委托。

每次业务调用和恢复校验当前身份、委托、对象权限和任务范围；过期时允许后端按合法机制受限续期，协议TBD。不能依赖浏览器持续在线。无法续期仅阻止受影响操作，保留可继续部分。重新授权后核对同一主体、范围及当前业务状态再恢复，不盲重放未知写入。

撤销/解绑/业务主体停用/权限收窄均阻止后续受影响操作，不回滚既有业务效果；Decision中的同意不创建委托。外部轨迹客户端授权单独展示与撤销，不因本人业务授权而自动可读平台记录。

## Core User Flows

### Flow 1：理解Context依赖并作出正式决定

1. 从Project进入执行A，或从业务系统深链进入同一Request。左侧显示进行/等待/可继续，右侧显示当前问题及影响。
2. 查看Context依赖列表，发现正文v2已取得、签署页缺失、正式效力待确认。点正文来源查看原文与版本，区分事实、假设和Agent建议。
3. 选择请求允许的判断、事实补充、限定授权或调查方式。判断无预选、理由必填；事实需来源，授权显示对象/动作/范围。
4. 核对Dialog显示Request、处理内容、理由和影响，说明不自动修改OM、不替代业务审批、不创建业务委托。
5. 提交前校验当前身份/权限、Request与业务版本，禁重复点击；接受后先显示处理已记录，后续实际事件出现才显示工作继续。
6. 调查请求只记录调查要求，不把原问题标为已解决。Project、业务系统演示页与工作台读取同一记录。
7. Context变化保留草稿并要求复核；结果未知先查询原操作，不重复发送或静默覆盖。

首次价值：用户无需通读完整轨迹，就能理解判断所需的信息依赖并完成可追溯处理。

询问只解释已记录事实，聊天里的同意不生成Resolution。取消通过更多菜单确认，先接受请求、再确认实际停止，保留已有业务效果与未知调用，不影响Project其他执行。

### Flow 2：外部Agent读取实践并在Git改进OM

1. 用户从执行进入 Trajectory/Episode，查看记录覆盖、Context 来源与实际使用 SHA。在指南或个人设置确认外部客户端身份与最小读取范围。模拟调用先校验对象权限与来源策略，授权不足返回拒绝而非空成功。外部 Agent 通过只读 MCP 分页取得授权轨迹/Episode 及必要引用；返回缺失/脱敏说明，记录读取审计，不交付令牌或未经许可的业务原文。外部专家使用 OME 反思模块分析并修改本地 OM，验证和讨论均发生在外部环境；Airic Work 不启动分析任务、不存储学习审阅对象。改动经 GitHub/GitLab PR/MR Review 合并。平台同步配置来源分支，展示新提交描述和文件差异。未来新 Execution 解析最新确认 SHA 运行；旧 Execution 仍显示原 SHA 及 Context 记录。

### Flow 3：配置OM来源并确认最新版本

1. 管理员填写仓库、来源分支和凭据引用，只读连通测试不启动执行。
2. 保存配置后显式同步。显示同步请求已记录，再显示完成、失败或未知；只有取得并确认远端来源提交才显示已确认最新。
3. 打开文件树阅读文档，查看历史提交描述和diff，编辑/Review跳转Git平台。
4. 同步失败保留历史可读，显示最后成功时间；新执行保持未启动并提示确认来源，不能自动用旧缓存伪装最新版。
5. 管理员重试后查询结果，不重复创建业务执行；现有执行的SHA不改变。后台同步频率/重试退避/时限为TBD。

### Flow 4：管理员创建用户，本人建立有效业务委托

1. 管理员新增用户，校验唯一登录标识；保存立即生成有效或停用账户，无邀请接受步骤。
2. 在业务身份页配置业务系统实例与稳定主体，经模拟目录验证；重复外部身份被拒绝，只填ID不能生效。
3. 用户本人在个人设置确认业务身份和授权范围，模拟授权后可只读测试。原型明确不连接真实认证服务。
4. 执行代表归属人本人的业务主体调用MCP；当前授权失效时提示本人重新授权，只阻塞受影响操作。
5. 重新授权核对同一主体和范围，取得后续事件才确认工作继续；管理员不能共享账号兜底。
6. 停用有责任用户、停用自身、降级最后管理员均被阻止并显示原因；历史记录保留。实际会话撤销/凭据联动由生产安全机制实现，原型不假报完成。

## Data Model & Backend

以下为原型展示模型，不是正式数据库、Schema或完整状态机。Context依赖通过可展示引用表达，不要求独立知识图谱。

| 展示对象 | 原型需要的信息 | 关系 |
| --- | --- | --- |
| OMSource/GitRevision/FileView | 仓库、来源分支、最新确认 SHA、同步时间/状态；提交描述、父 SHA、文件及 diff | Git 为权威；本实例为单一仓库配置，OMSource 表示实例级唯一来源，不能作为多仓库列表管理 |
| Execution | ID、projectId、ownerId、目标/范围、实际 OM SHA、Runtime/Skill 版本、身份快照、进展/结果 | Execution 保存其来源引用与实际使用的 SHA，不提供运行时 OM 选择 |
| 其他模型 | Request/Resolution、Decision Context、TrajectoryEvent/Episode、BusinessIdentityLink、DelegationView、ExternalReadGrant、Connection/RuntimeInfo、Preference/Notification、AuditRecord | 按原定义保留；OMSource 的语义调整为实例级单仓库来源 |

模拟服务包括查询/取消执行、查询/处理Request、查询后续、同步/读取Git文件与历史、读取轨迹/Episode、只读MCP授权检查与分页读取、用户创建/编辑/启停、身份验证、本人授权/撤销、配置及偏好保存。没有平台内分析、学习发现、候选修订或邀请服务。

标准API仍表达创建/查询/取消执行及Request查询/处理，调用方和实际用户需可信关联。创建幂等，接受不等于实际执行，取消不等于已停止。公开HTTP路径、MCP工具名、认证/通知协议均TBD，页面路径不是正式接口。

外部读取服务复用授权后的记录查询，不复制一套轨迹。每页读取均受当前授权及数据策略限制；分页快照、体积限制、保留策略与敏感字段规则需详细设计。权限不足不泄漏对象存在性、内容或计数；读取审计记录客户端/用户、范围、时间、结果，不把秘密写入日志。

生产秘密在服务端安全托管，Agent/浏览器只取得必要能力，不接收可任意冒用的凭据。原型localStorage只保存虚构ID与状态；用户切换隔离草稿/缓存/委托。创建身份快照与调用历史不可因重新授权或映射变更改写，不能以历史有效覆盖当前失效。

## Key Components

### Decision Brief与依赖列表

呈现顺序为问题/动作、触发和影响、建议及不确定性、Context 依赖、事实/假设/缺失、候选方案风险、来源与 OM 修订。依赖项用 Table/List 配 Chip 显示信息可用性，点 Link 进入详情，不构造复杂关系图。无依据可显示无建议，不自动填答案。文件阅读器基于本实例唯一仓库，支持文件目录与全文搜索（针对当前已同步的提交快照），并在命中文件中高亮匹配片段。

处理表单使用FormControl、RadioGroup、TextField outlined和FormHelperText；理由multiline minRows 3。sticky底栏p2、background.paper、顶部分隔，唯一contained按钮下一步：核对并提交。Dialog maxWidth sm，返回修改与明确命名的提交操作。

### Context详情Drawer

temporary Drawer覆盖工作区，不成为第三常驻列。业务事实显示权威来源与版本，文档显示定位与原文/摘要区分，既往决定显示正式记录，授权显示适用范围及当前有效性。无访问权/已清理/加载失败/缺版本分别提示，不以摘要替代核验；关闭保留草稿并恢复焦点。

### 文件阅读器与 Git 差异

安全渲染 Markdown/文本，保留文件路径与完整 SHA；相对链接限定同仓库同修订，禁用不安全 HTML。历史视图清晰标识，提交描述与差异同屏关联。主文件阅读器基于本实例唯一仓库：页面顶部摘要显示仓库、配置分支、最新确认 SHA 与同步状态/时间；主区域直接展示文件目录、全文搜索和正文，历史以 Tab 或链接进入。未配置仓库时显示未配置空状态并提示管理员前往 Git 设置；未同步或同步失败保留明确提示，不提供新建 OM 入口。

### Trajectory与Episode查看器

MUI Table/List、分页、Accordion和Drawer组合；事件有稳定定位，过滤可恢复。区分调用发起与实际回执，保留缺失和脱敏限制。Episode链接至当时的Context引用和固定文件修订，不提供平台内分析或采纳按钮。

### 只读MCP模拟面板

显示调用客户端/用户、所请求资源范围、授权检查、返回的虚构记录、分页和读取审计。只读调用可成功或拒绝；越权、失效授权、不可外发字段均不能绕过。演示面板不代表真实MCP Endpoint，不自动连接本地Agent、不回收外部学习结果。

### 管理表单与身份保护

设置和个人偏好统一脏值保护、显式保存/恢复。技术连通测试不等于业务本人授权，映射验证不等于可执行操作。账户与映射变更确认影响，防最后管理员自锁和责任丢失；所有模拟服务同样校验，不能仅隐藏菜单。
