# OM Work

**Operating Model（OM）是一个项目对如何开展工作、如何作判断的约定。** 它告诉人和 Agent 要交付什么、根据哪些信息判断结果是否合格、哪些情况要请人决定，以及得到答复后怎样继续。

先读项目的根 OM（通常是 `om.md`），确认本次任务的目标、对象、范围、方法版本和可用工具。沿入口找到当前工作类型，再按需读取相关的判断方法（Decision）、依据和已采用的案例。优先查可获得的业务记录、资料与工具回执。按 OM 的接受条件和强制过程推进已委托工作，核验实际产出。证据缺失、方法缺口和工具或权限限制分别记录。

## 检查与同步 OM 版本

用户可以直接说「打开团队的 OM」「检查有没有新版」「把本地 OM 更新到团队版」或「把这几项方法改动发给团队评审」。由 Agent 使用当前宿主授权的 Git 或仓库工具处理，并用用户熟悉的工作语言说明结果。

- **打开或连接**。先找当前项目的根 OM 和已有仓库。项目已连接时，沿用它配置的来源和分支。首次取用时，从用户提供的地址或已确认的项目来源下载到独立目录。新建本地 OM 可以先在本地工作，用户要求连接共享仓库时再核对目标仓库和分支。仅在目标有歧义时请用户选择。
- **检查有没有新版**。读取当前分支、已保存的版本和本地改动。能访问共享仓库时，先查共享分支的最新版本，再比较两边。只问状态时，保持工作文件原样，并说明两边一致、共享版有更新、本地有待分享的改动，还是双方各自改过。只能读附件或本地文件时，按当前可见版本工作，并说明共享版本尚未核对。
- **更新到共享版**。用户要求更新且可直接接上共享历史时，用只允许快进的方式更新，例如先 fetch，再对确认的目标执行 `git merge --ff-only`。更新前检查本地草稿、未保存为版本的文件改动，以及双方是否各自有新版本。有风险时保留现状，说明涉及哪些文件或方法，再让用户选择继续用本地稿、另开目录查看共享版，或核对如何合并。保留用户的草稿和历史，避免用强制覆盖、重写历史或清理文件来完成同步。
- **分享方法改动**。先让用户看得懂本次改了什么、适用于哪里，以及哪些还待验证。按用户委托把相关 OM 文件保存为一个 Git 版本，检查是否混入其他工作、`.ome/` 作者资料、业务原始证据或凭据。用户明确要分享时，按项目约定提交到评审分支或发起合并请求，并核对远端回执。保存本地版本、发起评审、采用和云端生效各有自己的确认依据。

同步后核对根 OM、实际版本和相关方法入口。用一句话交代现在能用哪版、用户的草稿是否还在，以及下一步是否需要选择。已按固定版本开始的工作按原依据续行；试跑新版时说明切换及受影响的判断。Airic Work 新任务实际采用哪版，以宿主的任务回执为准。

## 发起 Decision Request

先用已有证据和获准工具解决可自行完成的问题。需要用户提供会改变下一步的事实、专业判断或授权时，把相同依赖合并成一个问题，并标明它影响的工作范围。对独立、可分别回答的问题分别提出。能够继续的工作直接推进。

准备一份在离开当前聊天后仍可理解的 Decision Brief：

- 用短标题标识对象与待决事项，用一句话说明需要用户回答什么。
- 只给会改变回答的背景、证据定位和主要不确定性。让事实提供者回答配置或观察，让具备权限的人作专业判断或授权。
- 有可区分的路径时，给出简短、互斥的选项及各自触发的下一步。按需给出建议和依据，允许自由补充、部分回答或暂不确定。
- 记录受阻范围、已完成结果的引用、回答后要核查或执行的动作。用这些信息验证另一个会话能否局部接续。

优先调用当前宿主提供的结构化提问或 Decision Request 工具，按真实合同提交并核对回执。选择工具时确认它是聊天内问答，还是会生成业务系统里的持久请求。宿主只提供聊天时，直接在对话中呈现 Brief，并用实际对话或工作记录关联回应。等答复期间继续独立工作；如果无事可做，说明当前结果、待决项及恢复点。

## 按回应接续

将回应关联到原问题、对象、范围与上下文版本。记录实际回答及已提供的理由，保留部分答复、犹豫或未知的原意。核对新资料和当前业务状态，只重判受影响的工作。更正应能回溯原答复及其影响。授权或业务确认按应用合同判断效力。

例如，测试计划缺少「维护时是否需要带电」这一事实时，询问实际操作条件，并说明回答影响哪些测试安排。如果对方只确认调试时带电，更新调试安排，将维护工况保留待核。检查清单中与该条件无关的部分可以继续。

## 把实践反馈用于改进 OM

发现重复求助、难以回答的问题、恢复时缺少的上下文，或桌面环境特有的依赖时，保留最小案例与可核查引用。在用户委托改进 OM 时，按同项目的 [Operating Model Engineering（OME）Skill](../operating-model-design/SKILL.md) 处理，候选放在作者侧 `.ome/`。案例保留当时可见的证据、实际提问、用户原意、恢复动作和结果。方法候选说明何时触发提问、谁能回答、最少要带什么上下文、哪些工作可继续，以及回答或更正如何改变下一步。

检查候选方法在目标云端宿主的固定 OM 和授权工具条件下是否可执行。用代表案例模拟没有桌面对话历史时提出请求、让出、收到部分回答或更正、只恢复受影响范围的过程。记录缺少的工具或上下文，供独立验证和采用时核对。保留已采用的业务判断与本次执行依据的关联。
