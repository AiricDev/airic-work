# 写作示例：从“什么算 good enough”发现 Decision

这是合成的 OME 教学与测试设计案例，所有要求和材料均为示例设定。它不证明写作 OM 已通过专家验证，也不规定所有写作工作都采用同样标准。

## 工作用途与评价分解

目标是给采购负责人准备一页内部简报，帮助比较候选供应商并确定下一步。示例输入只有：需求说明、两个供应商的报价与演示记录。A 交付较快但只有供应商自测，B 有客户试用记录但总成本尚缺一项；具体数值以所给材料为准。

本例用户要求简报包含建议、主要取舍、依据和未决事项；允许条件性建议。示例组织规则要求关键事实可追溯，正式发布前必须由未参与撰写的人复核；本轮只交付待审草稿。用户偏好简洁、先呈现建议，偏好可随用途调整。这些来源分别构成接受约定、Mandatory How 和可权衡偏好。

| Evaluation Decomposition | 候选判断内容 |
| --- | --- |
| 什么算 good enough？ | 负责人能理解选项差别、建议依赖什么条件、现有证据不能支持什么，以及下一步该取得什么信息 |
| 何时拒绝？ | 杜撰数字/验证结果，隐藏会改变建议的未知，把供应商主张写成独立验证，把待审草稿写成已批准发布 |
| 怎样比较？ | 结合当前优先目标，在交付速度、证据强度和成本不确定性之间权衡；不预设固定权重或唯一最佳文风 |
| 何时停止？ | 决定性缺陷已修复、草稿可支持下一步且限制清楚时，额外修辞收益不足以抵偿时间成本即可停止；缺关键证据时转为条件性建议或未决 |

候选 Decision：**当前简报足以支持什么范围的采购建议，哪些限制必须保留？** 接受、候选比较、优先修订和停止可作为该问题中的紧密相关判断。若后续发现供应商风险判断与简报可用性有不同依据和复用范围，可拆成关联 Decision；不为每段、每轮润色或每条检查机械建文件。

## 提取什么，放在哪里

| 既有内容位置 | 本例候选内容 |
| --- | --- |
| Objective / Applicability | 内部比较与下一步安排；不支持签约或发布已批准结论 |
| Context Dependencies | 受众与决策用途影响详细程度；用户优先目标影响权衡；报价版本和证据来源影响事实/验证强度；缺成本项限制最终比较 |
| Judgment Basis / Method | 区分事实、供应商主张与推断；保留会改变建议的未知；按用途评价论据与可用性，再比较表达效果；事实失真优先于文风改进 |
| Constraints / 工作骨架 | 保留关键事实来源，正式发布需独立复核；复核者、实际结果和版本须可核对。来源不充分时不能补写事实，待审状态不能冒充已批准 |
| Outcomes | 可用待审草稿、条件性建议、多案并列、需补证/修订或升级；判断结论可以含不确定性 |
| Precedents / Knowledge Gaps | 经验证采用的正反例与边界解读；若组织对可接受试点风险没有可用判据，保留判断知识 Gap |

缺报价中的一个成本项是本案事实缺失，应安排取证；“组织如何在时间压力与试点风险间取舍”可能是持久性判断知识 Gap；谁能批准发布属于实际权限合同。不能把三者都写成等待专家补齐 OM。

先列提纲、先写草稿再重组、使用表格或短段落属于 Discretionary How，均可在约定内尝试。示例组织要求的独立复核与来源留痕属于 Mandatory How。专家习惯“先列七点提纲”不自动成为强制过程。

## 用对照提取判据

请专家比较具体片段，而非要求描述完整写作 SOP：

- “A 交付更快，但验证证据仅来自供应商；建议先安排限定范围试用，再决定是否扩大采购。”在本例内部用途下是否可接受？需限定什么范围？
- “A 已经客户验证，建议直接签约。”与输入不符；文辞更有说服力不能补偿事实失真。
- 若简报诚实列出成本未知，但不作最终排名，是否仍能支持下一步？什么新增事实会改变接受范围？
- 两份草稿事实相同，一份先给条件性建议，另一份先列比较表。当前受众偏好哪份，偏好理由能否推广到其他受众？
- 再改十分钟主要改善句式，而成本证据需另行等待，此时应继续润色、交付待审草稿还是提出补证？为什么？

这些问题用于取得有来源的判据与边界。示例中的预期不替代实际专家评价，不把事后解释冒充当时理由。

## 预先写下的合成验证场景

以下是待执行的 Test Case 设计；预期来自上述示例任务和组织规则，没有真实运行结果。

| 场景 / 最小变化 | 允许的判断或观察重点 | 禁止推断 |
| --- | --- | --- |
| 正例：不同结构的两份草稿均准确保留取舍、来源、未知与下一步 | 都可成为可用待审稿；偏好可有理由地不同 | 只有某种提纲/措辞才合格 |
| 反例：把供应商自测写成客户独立验证 | 识别关键事实错误，优先修复，再评价建议 | 因文风流畅或作者自评高分而接受 |
| 边界：缺成本项，提出有条件的试用建议 | 在明确限制下可能支持下一步，最终排名保持未决 | 试用建议等于已证成最低总成本或最终采购批准 |
| 对照：事实相同，用途由内部探索改为签约依据 | 重新评估所需证据、可接受风险与结论范围 | 沿用原草稿的接受范围而不重判 |
| 优先级：同时存在来源误述与句式不够简洁 | 解释为何先修事实；其余改进结合成本判断 | 所有质量维度同权或可相互抵消 |
| 停止：草稿满足用途，只剩不影响使用的修辞改进 | 可以停止润色并交付待审稿，说明仍待补证或复核的事项 | 为等待外部信息无期限润色，或因超时宣称已可签约 |
| Mandatory How：文稿质量足够，尚无独立复核记录 | 草稿可待审；正式发布条件尚未满足 | 以作者自检代替要求的独立复核 |

实际验证应另外取得未参与提取的材料或独立专家评价：预先保留评审判据，只向执行者提供任务、原始材料与候选 OM；核查事实来源、理由、允许的多案结果与过程证据。独立 Agent 前向练习可检查指引是否可用，不能证明采购领域判断正确。由作者生成以上案例后自测，只能报告合成自检；没有独立证据时，相关验证仍未完成。

形成真实 Episode 后，按 [案例契约](artifact-contracts.md) 保存实际判断、理由来源、结果与迁移边界，再依既有审阅采用机制形成 Precedent。当前示例继续标为合成材料。
