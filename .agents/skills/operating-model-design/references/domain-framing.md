# 利用模型的领域知识与专业视角

在选择领域表述、借助模型提出候选方法或设计角色提示时使用。以下是待具体任务验证的设计指导，不保证某种措辞提高模型准确率。

## 主动用模型提出方法

OM 作者可以让模型：提出常见工作路径、发现遗漏依赖、给出能改变决策的条件、生成反例、比较候选拆分、准备专家访谈问题。执行 OM 的 Agent 也应能在明确目标、依据与权限下选择适合的方法，不必把所有情形枚举完才行动。

不要把模型当空白执行器，也不要把熟练表达当作已经核实。区分两种用途：

- **提出候选**：用一般知识生成方法、假设、关键术语和调查方向。明确可证伪条件，不需要每个常识都转化成资料请求。
- **支撑业务结论**：项目事实、精确版本的规范要求、阈值、资质、既有执行结果必须有相应依据。模型建议不能自动成为权威规则或项目证据。

模型提出了可用概念，仍要问它改变了哪个观察、判断或行动。没有实际影响的术语无需进入 OM。

OM 无需重写领域百科。优先外显组织特有的做法、容易混淆的区分、精确适用边界、模型反复遗漏的判断及人机交接约定；一般知识可以供模型按需运用。哪些内容需显式化，应由实际行为与风险决定，而非假设模型必然知道或必然不知道。

## 选择领域表述的方法

1. 从实际条文、业务合同、专家语言和案例中收集决定行动的概念。模型可补充候选，作者核对其含义。
2. 区分容易混淆的概念及适用范围，例如“交付完成”与“专业接受”、“观察事实”与“推断”。组织内部含义不同于通用含义时，就地解释。
3. 为专业方法注明使用条件、要查看的事实、要区分的情况、预期产物和停止/升级条件。避免只写一个方法名让执行者猜测。
4. 用案例观察这些表述是否带来所需选择。不要因为术语更多或答案更像专家就认定更有效。

可以把领域语言视为向模型说明任务和关注点的接口；“精确术语能唤起相关知识”是有用的设计假设，不是对模型内部机制或可靠性的证明。

## 角色提示可以用，但需要工作内容

“你是一名……专家”可以简短定位职责、对象和专业视角。避免堆砌名望、虚构从业年限或资格，也不要让角色声明改变系统权限。

优先写成：

> 以【领域角色/视角】协助完成【业务目标】。重点检查【领域概念与关键区分】，依据【来源与适用范围】选择【方法/行动】；交付【可核验产物】。可以主动提出【候选方法与遗漏】，关键事实不足时说明缺口及下一步。

这是可选结构，不是所有 OM 必须插入的一段话。清楚的任务描述已覆盖这些信息时，可以省略角色句。只要求可核验的判断摘要、依据与产物，不要求展示完整内部思维链或模拟冗长专家独白。

例如在设备标签评估中，可写：

> 以设备安全评估工程师的视角协助本次标签评估，区分危险、暴露场景、已有控制措施与警示信息；依据当前条款和实际设备资料判断尚需确认的事实。可以提出潜在遗漏和检查方向，并说明依据或假设。需要现场事实时形成可执行核查要求；精确条文、判据和已检查结果从实际来源取得。交付有依据的草稿或有明确去向的取证工作。

这里的概念是方法候选，不代表某个标准要求固定执行这套分析，也不授权模型替代专业确认。

## 检验角色与领域表述是否有用

按需要比较：A 清楚的任务/上下文；B 在 A 上增加简短角色；C 在 A 上增加具体领域概念、关键区分和产物要求；必要时再比较 B+C。保持模型、资料、工具和任务相近，记录差异，不将 C 的收益归因于角色句。

看关键判断、遗漏、任务可执行性、依据正确性和回传接续，兼顾过度自信与无谓停等。相同目标下较短的表述若表现相当，优先保持简单。重要场景重复观察；效果不稳定则限定适用范围或撤去该提示。

## 证据边界与参考

以下来源支持把角色与具体指令分开考察，并不验证本 skill 的 OM 工作流：

- [OpenAI Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering#message-formatting-with-markdown-and-xml) 将身份、指令、示例和上下文分别表达。这里据此采用分开设计的做法，不推断角色本身增加专业能力。
- [When “A Helpful Assistant” Is Not Really Helpful](https://arxiv.org/abs/2311.10054)：对所测模型与事实问答，角色提示没有带来总体性能提升；个别角色效果有差异。不能直接外推到所有模型和长期 Agent 工作。
- [ExpertPrompting](https://arxiv.org/abs/2305.14688)：定制、详细专家描述在其指令回答实验和模型评估中有收益；其方法与简单添加“你是专家”不同，不能据此承诺事实准确率提升。

来源用于说明不确定性和设计选择。实际 OM 的采用以当前任务的验证为准。
