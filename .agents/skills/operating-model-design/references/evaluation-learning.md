# 行为验证与 Reflective Learning

用于验证候选 OM、从实践形成改进，或单独开展反思。反思模块可只读取授权证据并交付学习候选，不要求加载完整初版设计方法，也不要求修改 OM。

## 先检验评价依据，再定义可观察预期

Verifier 是审视 Decision 的视角：什么依据能支持或推翻判断，谁能评价，允许哪些结果，证据不足时怎样处理？它可以由规则、专家比较、后续效果或受控检查实现；文档描述不证明宿主已有自动 Verifier 服务。

先核对评价依据：来自哪个规则版本、用户目标/偏好或专家经验，适用于何种对象，哪些仍是候选。再用它评估实际判断。候选规则和候选案例相互吻合，只能说明内部一致；它们不能相互证明专业正确性。

| 判断形态 | 可观察的验证重点 |
| --- | --- |
| 接受 / 拒绝 | 用途是否满足，缺陷与证据边界，拒绝理由是否成立 |
| 选择 / 权衡 | 为什么偏好某案，关键目标变化后是否合理反转；可接受多案和不可比较范围 |
| 诊断 | 解释与事实是否相容，竞争解释是否被遗漏，什么额外证据能区分 |
| 优先级 | 风险、影响、紧迫性、依赖与代价是否支持排序；并列或次序不确定是否有理由 |
| 不确定性 / 升级 | 哪些结论不能成立，限制是否具体，何时补证或由有权者处理 |
| Good Enough / 停止 | 接受条件是否满足，继续改进价值与成本是否相称；资源耗尽是否被误当成合格 |

评价可以保留主观偏好、合理分歧和多维权衡。有可靠定义和校准时才量化；不能为自动评分强造权重，也不把与唯一参考答案措辞不同当成错误。测试协议可以判定一次观察是否满足预期，领域 Judgment 本身仍可包含多种结论和不确定性。

## 定义案例与验证范围

为代表场景说明起始状态、事实与缺口、可用能力、预期判断/范围/行动/产物、禁止推断，以及相关反馈和恢复条件。在观察运行前确定判据、允许的结果范围和未能判定时的处理；不要按生成结果事后移动标准。发现预期有误时保留修订理由和版本，并用新的未参与修订案例复查。

按关键区分选择能推翻过宽规则的案例，不要求穷举：

| 案例 | 应揭示什么 |
| --- | --- |
| 正例 | 有哪些不同做法或不同结果都能满足评价条件，避免只学到一个模板 |
| 反例 | 看似流畅/完整/成功但有关键缺陷，是否能被识别和拒绝 |
| 边界例 | 勉强可接受、部分支持、合理分歧或证据不足时，判断范围是否恰当 |
| 对照案例 | 尽量只改变一个决定性条件，选择、优先级或停止决定是否相应变化；无关变化是否误导判断 |
| 过程约束例 | 成品可用但违反 Mandatory How 是否被识别；不同 Discretionary How 满足要求时是否仍可接受 |

缺输入、冲突、部分回传、版本变化或中断恢复按本次范围选用。分别检查判断是否受证据支持、工作是否形成可用产物，以及人工反馈后能否有效重判和继续。案例的实际、重建或合成来源需明确。

## 保持验证独立性

把用于提取规则的材料与未参与编写的验证材料区分。根据风险与可得证据，使用预留真实案例、未向执行者展示的专家评价、精确来源核查、独立复核或后续可观察结果；验证范围与独立性如实记录。

作者自检可发现遗漏，合成案例可检查逻辑；同一 Agent 同时生成规则、用例与预期后自评，不能作为独立确认。另一个 Agent 在不接收作者结论或预期答案的条件下前向执行，可减少上下文诱导，但共享模型、资料和假设仍会造成相关错误；它不能替代领域权威或独立业务证据。

验证前固定候选版本和评价依据，向执行者只提供完成任务所需的输入、方法与工具；将不应泄漏的评审答案、作者解释和预期缺陷留给评价者。验证材料一旦用于修改规则，就已成为开发材料；后续迁移主张需新的独立材料支撑。独立来源不足时，明确“自检 / 合成推演 / 待独立验证”，保留相关 Gap，不能因输出合理就关闭。

评审者分歧需检查目标、来源、上下文和偏好差异，保留理由与未决范围。当前事项获有权者接受，与规则普遍有效是两项不同结论。

## 记录实际验证强度

| 验证方式 | 能支持的结论 | 仍不证明什么 |
| --- | --- | --- |
| 静态检查 | 结构、引用、来源要求和合同映射一致 | Agent 会作出正确判断 |
| 人工/Agent 情景推演 | 候选方法在所设场景中的逻辑和覆盖 | 真实工具、真实协作可以闭环 |
| 模拟工具执行 | 指定输入下的调用、引用和恢复行为 | 开放专业场景中的稳定性 |
| 真实 Agent 受控运行 | 指定模型、知识、工具和版本下观察到的行为 | 对所有模型、领域和环境均有效 |

重要分岔适度重复，记录实际样本、覆盖与混杂因素。结构完整和一次成功仅支持有限结论。测试与真实业务操作遵循已有授权，不能为了取证自动重放历史写入或外发历史资料。

## 验证入口、路由与案例归属

涉及整体结构时，从代表性请求和可用业务上下文出发，检查 Root 是否足以选择工作类型、定位方法并取得所需知识；再选歧义请求、未知工作类型或入口不可达等与本次变化相关的场景。Root 没有直接 Decision 不构成缺陷，关键是实际导航能否到达执行所需方法。静态链接可达不证明宿主已将固定版本装配进 system prompt，装配与运行来源按实际记录核对。

涉及案例组织时，检查来源、实际理由、后来的解读和采用状态是否可区分；同一事件用于两个 Decision 时，各自的判断用途和迁移限制是否明确。共享来源不应迫使共享结论，多个文件也不应重复维护公共事实或完整解读。

## 单独调用 Reflective Learning 模块

输入是可访问的 Episode/Trajectory、当时目标、相关 OM/Skill/指令及版本，以及可选的历史案例。优先读取能解释事件的最小证据片段，用确定性工具核对引用、版本和回执；不要求 Agent 生成系统本应保证的不可变证明。

| 动作 | 要解决的问题 |
| --- | --- |
| Observe | 原预期是什么，实际发生什么，人工介入或意外结果在哪里？ |
| Reflect | 关键差异可能意味着什么，哪些条件重要，有哪些竞争解释？ |
| Attribute | 问题或收益涉及判断知识、上下文、执行方法、能力、交互，还是目标变化？ |
| Propose | 有什么有限范围的知识候选或最小改进，预期改变什么，如何检验？ |
| Synchronize | 人是否理解观察、解释与限制，其补充、纠正和判断理由是什么？ |
| Revisit | 候选被采用、拒绝或修正后，后续效果是否支持原解释？ |

这些动作可往返；证据不足时可以停在明确未知和下一步取证。单独反思不默认取得修改、发布或继续业务执行的权限，后续工作依现有授权接续。

## 比较归因，不把每次偏差变成规则

| 候选解释 | 应查什么 | 可能承接位置 |
| --- | --- | --- |
| 方法缺失、含糊或冲突 | 实际可见方法是否指导该区分、是否相互抵消 | Decision/公共约束 |
| 知识未进入上下文 | 实际加载版本、工作类型选择、知识路由与获取结果 | Root/子 OM 导航、依赖或运行机制 |
| 专业知识不足/不适用 | 标准版本、对象范围、必要依据和专家反馈 | Subject Knowledge、Decision Gap |
| 工具合同/能力问题 | 请求响应、权限、状态和回执 | 业务能力或宿主实现 |
| 协作与反馈入口问题 | 人是否能理解、回应、关联、补证，执行是否恢复 | 产品交互/工作骨架 |
| 目标或偏好变化 | 判断前后目标、约束与授权是否一致 | 当前工作或适用条件 |
| 局部执行偏差 | 同条件下的成功与失败记录 | 继续观察或执行方法 |

多个解释可同时成立。缺少加载记录、理由或结果时降低归因强度。专家纠正和一次成功都是证据来源，不能单独证明因果。设计能够区分解释的检查，例如先核对实际加载，再比较更明确的方法。

## 交付 Knowledge Delta 和最小候选修订

按范围合并表达：观察与证据；原因解释、替代解释及限制；拟改变的知识/能力与适用范围；预期行为变化；原场景与相邻案例验证；实际采用状态及复查条件。

改进预测应可被推翻：这些条件下哪些判断/产物应改变，哪个相邻场景的正确行为应保持。优先一次检验一个有解释力的变化，避免同时更换模型、工具和大量指令后将收益全归给 OM。

目前不改 OM、保留分歧、补充证据或交给其他责任方，都是有效结果。修改后关联目标 Decision、来源 Episode、知识版本和实际验证证据；历史通过现有版本与记录保留。

## 检验 Decision 组织假设

若任务是评估本版 OME 本身，可分别研究：

1. **组织收益**：知识内容相近时比较过程式与 Decision 式组织，控制或记录上下文预算、模型、工具和任务差异。
2. **提取收益**：新增专家知识与案例后，在未参与编写的相邻案例上检验迁移，避免只在原案变好。
3. **反馈收益**：观察 Brief、理由采集和案例采用是否减少重复纠正，同时计入专家阅读、核对和维护成本。

关注判断质量、证据支持、可用产物、遗漏升级与过度停等。不要把新增知识的收益直接认作聚合方式的收益。错误未集中在判断处，或组织成本超过收益时，应调整方法假设和使用范围。

## 采用后复查

候选方法、验证通过与正式采用分别记录。按现有用户授权、专业审阅和 Git/宿主流程采用；不额外创造逐项审批。个人观察推广为组织规则需与实际证据和治理范围相匹配。

采用后观察收益与退化：强调证据是否造成无谓停等、减少求助是否遗漏必要升级、增加案例是否引入错误迁移。新证据出现时收窄、修订或撤回适用方法，通过正常版本演化保留历史。

如需表达 Readiness，分别描述判断覆盖、关键 Context 可取得性和实际验证程度，按明确场景说明可自主、需协助或受阻的范围。证据不足标未评估；Readiness 不等于成功率、统一自动化百分比或最终专业签署授权。
