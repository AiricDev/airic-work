# SEMI S2 示例：围绕“是否需要现场核查”组织判断

这是 OME 推导示例，包含候选规则与合成情景，不是经验证的认证 OM、现行标准条文或真实工具运行证据。实际使用需读取精确标准版本、适用要求、设备资料和业务合同。

## 从已有问题发现热点

案例材料描述：Agent 识别标签资料不足并保存草稿，后续只在聊天提出补充调查，没有形成可承接事项。仅此不能证明 OM 缺规则，还要核对实际加载方法、现有事项、工具、授权与业务状态。

工作用途可定义为：工程师能够承接明确核查，评估者能据回传继续判断。必要骨架是取得证据、形成受证据约束的判断、安排未决工作并在回传后恢复。

先做 Evaluation Decomposition，而非先要求列出检查 SOP：

| 评价问题 | 本例的候选区分 |
| --- | --- |
| 什么算 good enough？ | 已支持的结论有明确范围；未决事实有具体、可承接的取证要求，回传后可接续 |
| 何时拒绝？ | 无依据的符合/不符合结论、缺资料直接等同缺陷、含糊或重复且无新增覆盖的核查事项 |
| 怎样比较？ | 比较补文件、现场核查、复用已有事项分别能解决什么事实问题；结合风险、证据覆盖与成本选择 |
| 何时停止？ | 在当前交付范围已有充分依据或已安排必要取证时停止重复调查；未决事实不自动变为已接受结论 |

Good Enough 可能是可用的有限草稿与取证安排，不一定是最终专业结论；最终接受仍需满足适用要求与专业权限。

候选 Decision 是：**为支持当前标签评估，是否需要现场核查，以及核查要解决什么事实问题？**

其热点在于区分资料缺失、实物状态未知、判据未知和已有反证。一次工具调用选择可能承载这些专业知识。若后续发现“是否充分”与“如何取证”有明显不同的依据和复用范围，可以拆分组合；本示例的聚合仍待验证。

## 候选知识内容

| 内容 | 示例候选 |
| --- | --- |
| Trigger / Applicability | 标签判断存在未决事实，且现场证据可能改变可支持结论；具体标准和设备范围另行确定 |
| Objective | 明确必须确认的事实与可承接工作，保留当前证据支持的判断 |
| Context Dependencies | 适用要求、对象/危险/配置、已有照片或文件的覆盖与版本、既有核查事项、实际可用能力 |
| Constraints | 缺资料不能推断实际缺陷；不以设计清单自动证明实际安装状态；具体专业要求、强制取证/复核过程需精确来源 |
| Method | 按证据的判断作用比较补齐路径，明确可接受范围、未决部分及停止/升级条件 |
| Feedback | 专家对取证必要性与范围的纠正、现场回传覆盖、后续复核及无法恢复的原因 |

Context 需要注明判断作用。例如照片是否覆盖当前设备和工况，会影响实物状态可支持到什么范围；既有核查事项影响是否复用及覆盖关系。资料名称本身不证明充分性。

| 观察条件 | 候选行动 | 仍需保持的边界 |
| --- | --- | --- |
| 必须确认实际存在、内容或位置，现有证据不能支持 | 创建或复用现场核查工作 | 明确对象、需确认事实、依据和回传要求 |
| 缺供应商文件或说明 | 明确承接的资料澄清 | 文件缺失不自动成为实物不符合 |
| “应检查什么”尚无依据 | 补齐判据/危险配置知识，保留可独立完成的取证 | 不给工程师含糊的“检查全部标签” |
| 已有实际反证 | 依业务合同处理相应问题 | 指明观察、适用要求与证据范围 |
| 已有充分依据或同范围核查 | 保存可追溯判断，或复用并关联工作 | 不为增加产出机械新建事项 |

这些分支需要真实领域来源与案例检验，不能按表直接作为标准判据。

在满足取证要求与权限时，资料阅读顺序、调查组织和草稿写法通常可由 Agent 探索。若适用条款、合同或业务规则要求某种现场验证、独立复核、签署或留痕，应核对其精确来源与范围，作为 Mandatory How 保留；不能因模型认为照片已足够而自行豁免，也不能从本例推导所有标签判断都必须现场核查。

## 提取尚未外显的经验

围绕具体案例向专家核对：什么证据使你认为必须现场确认？哪些照片足够、哪些看似清楚仍不够？什么观察会改变原方案？何时可以停止？哪些设备/工况会形成例外？

将回答与当时记录区分，再在一个只改变证据覆盖或设备范围的相邻案例上检验候选方法。理由取得不到时保留未知。

## 合成的 Brief 与反馈路径

可准备这样的简短 Brief：当前对象和适用要求是什么；已有证据能支持到哪里；未决的实物事实是什么；建议核查什么及理由；请专家确认必要性与范围。附决定性证据和版本引用，完整材料按需查看。

若专家认为现有照片已经充分，应记录实际依据和覆盖范围，核对后修正当前取证安排。若批准现场核查，批准本身仍不证明该方法对所有情形必要。上述回应是合成分支，不代表已有专家实际作出这些判断。

工程师回传后核对原要求、对象、版本及覆盖。部分回传只支持相应部分重判；上传不等于工作完成或专业接受。通过已有 API 更新业务对象并核对回执，保留 Episode 引用。

## 验证与可能的知识沉淀

比较资料充分、部分缺失、判据未知、已有共同任务、部分回传、要求更新和真实反证等有关场景，检查恰当取证、判断边界及恢复。预期收益是可用工作和更好的判断，不是任务数量增加。

设计正例、反例和边界对照：同样清晰的照片，覆盖全部当前对象与仅覆盖部分对象时，允许结论范围应不同；同样的清单缺项，尚无实物事实与已有实物反证时，不能给出相同的缺陷结论。再检查不同取证组织能否满足同一要求，以及成品看似可用却缺强制过程证据时是否保持限制。上述仅为合成预期，应在运行前结合实际权威要求核定。

原问题用于发现候选规则；另外保留未参与编写的案例、独立专业评价或后续现场证据，核对允许的结论和行动范围。另一 Agent 用本例生成更多相似场景再自评，不能替代这些证据。

实际专家理由、回传和后续结果取得后，才可构成相应真实 Episode。经反思、适当验证与采用，可形成说明某项关键区分的 Precedent；合成示例继续保留合成标记。具体标签判据、阈值、条款结论和工具状态不得从本例泛化。
