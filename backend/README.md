# Backend

Airic Work runs as a headless OM Worker. The backend retains the internal Execution domain, SQLite control store, Pi Durable runtime, OM snapshot and MCP adapters. The Task API and Swagger UI are available for testing. Compose configures isolated Workspace commands for the Worker. Production acceptance is pending.

Run `npm run check` at the repository root for type checking and backend tests. Some integration tests start a local HTTPS server and require loopback access. The target contract is [OpenAPI](../docs/openapi.yaml), and the transition is described in the [technical design](../docs/technical-design.md).

The local Task HTTP entry point supports `POST /api/v1/tasks` and `GET /api/v1/tasks/{taskId}`. Set `AIRIC_TASK_DATA` to a private data directory, `AIRIC_SECRET_KEY` to a random Bearer token of at least 32 characters. Run `npm --prefix backend run task:http`. It binds to loopback on port 8080 unless `AIRIC_TASK_PORT` is set. Task creation supports an instruction, OM selection, optional context, uploaded materials and MCP connections. Enable the local worker with `AIRIC_TASK_WORKER=1` and configure `AIRIC_OM_SOURCES`, `AIRIC_MODEL_PROVIDER`, `AIRIC_MODEL_ID` and `AIRIC_MODEL_API_KEY`. The worker accepts configured OM tags or full commit IDs. With the worker enabled, the Task detail includes the Session and pinned OM after preparation, and decision requests can be listed under the Task and answered through the user-decisions endpoint. For MCP, set `AIRIC_TASK_MCP_ALLOWLIST` to a JSON array of HTTPS endpoint prefixes and optionally set `AIRIC_TASK_MCP_SECRETS` to a JSON object mapping secret references to Bearer credentials. The worker can discover and call authorized Task MCP connections. Uploads can be attached to Tasks and read through the UTF-8 attachment tool.

For service-to-service requests, use the same `AIRIC_SECRET_KEY` and follow the [service authentication contract](../deploy/README.md). The Task API credential and the Task MCP connection credential serve separate endpoints.
