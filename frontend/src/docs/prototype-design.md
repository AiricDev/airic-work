# Airic Work 产品交互与原型设计方案

## Product Overview

Airic Work 以 Operating Model（OM）驱动后台自主执行，以 Decision Request 组织人工介入，以 Trajectory 支持实践学习。工作台连接业务系统的大任务、多个 Agent 执行、知识版本与学习证据，让用户集中处理真正需要负责的判断，而非持续监督聊天。

依据为上传文件 prd.md，重点包含第 2—10、12、14 节，以及本线程确认的 Project → Execution 层级、任务单一归属人、MUI 设计体系和单组织最小管理范围。PRD 确定产品职责；本文进一步提出页面、交互和模拟数据结构，不代表功能已经实现，也不固定公开 API、数据库或 Runtime 状态机。

范围包括：

* 工作：Project、Execution、Decision Queue、证据、受控取消与执行询问。
* 知识：Git-native OM 只读浏览、Decision 关系、Knowledge Gap、版本和验证记录。
* 实践：Trajectory、Decision Episode、学习发现、改进候选、人工反馈与 Git 关联。
* 管理：单组织系统设置、管理员/成员、成员邀请与停用、个人资料与通知偏好。
* 集成：标准任务与决策 API 的接入说明、业务 MCP、Git、Runtime/Skill 能力与版本展示。

不在平台重建 OM 编辑器、Git Review/合并、通用 Deep Focus Agent、业务系统权限或专业审批。不提供对外 MCP。业务系统仍是执行创建主入口；本轮不增加通用手动新建执行表单。

## Design & Visual Style

### 组件与主题

采用 @mui/material、@mui/icons-material、@emotion/react、@emotion/styled。使用 ThemeProvider、CssBaseline、createTheme；布局使用 Box、Stack、Grid 与 sx。不混用 Tailwind、shadcn 或 Lucide。若原型环境无法使用 MUI，明确报告限制，不将视觉近似宣称为 MUI 实现。

* 浅色主题，primary 采用 MUI 默认蓝，background.default 使用 grey.50，面板 background.paper，边界 divider，文字 text.primary/text.secondary。
* 沿用默认 typography、shape、交互状态、阴影和焦点。字体使用 Roboto、Noto Sans SC 和系统无衬线回退，ID/Commit 局部等宽。
* 页面标题 h5，执行及详情标题 h6，区段 subtitle1，正文 body2，较长说明 body1，次要元信息 caption。
* 默认 8px spacing；桌面页面 padding 3，窄屏 2，面板 3，区块 gap 2，元信息 gap 1。
* Paper 以 outlined、elevation 0 为主；临时 Drawer/Dialog 使用默认层级。不做渐变、玻璃拟态、巨型数字卡或装饰流程图。
* 表格使用 MUI Core Table、TablePagination，紧凑表行最小约 56px；筛选使用 size small 的 TextField、Autocomplete。

### 全局布局与响应式

桌面主画板 1440×900。顶部 AppBar 高 64px，浅色背景与底部分隔；左侧 Drawer 宽 240px。移动 AppBar 高 56px。主操作一屏一个明确方向，高风险动作置于更多菜单。

lg 及以上常驻侧栏；md 到 lg 使用临时导航。执行详情在空间足够时使用左右 Grid：minmax(0,1.1fr) minmax(420px,1fr)，gap 2，不开发拖动分隔线。小于 md 使用执行/待决单栏 Tabs。证据 Drawer 桌面 640px、窄屏全宽；移动 Dialog fullScreen。表格只在自身容器内横滚，页面不能整体溢出。

桌面执行详情左右内容独立滚动，标题和提交操作区可见，底栏不遮内容；其他页面使用常规页面滚动。键盘焦点、模态 focus trap、关闭后焦点恢复使用 MUI 能力。状态始终有文字，遵循减少动态效果偏好。

### 统一反馈

| 情况 | 组件与呈现 | 行为 |
| --- | --- | --- |
| 进行中 | info outlined Chip | 不显示无可测分母的百分比 |
| 需要判断 | warning outlined Chip | 进入具体 Request |
| Agent 执行结束 | default outlined Chip | 不等于业务完成 |
| 已记录决定 | 持久 success Alert | 等待实际执行反馈 |
| 等待恢复 | info Alert | 列出依赖，不重复提交 |
| Context 更新 | warning Alert | 保留草稿，重新核对 |
| 失败 | error Alert 与字段说明 | 保留输入，允许针对性重试 |
| 结果未知 | warning Alert | 查询同一操作，不盲目重放 |
| 断连/同步失败 | 顶部 warning Alert 与最后同步时间 | 缓存不能伪装实时 |
| 加载 | Skeleton 保留布局 | 局部失败不清空整页 |

Snackbar 只用于复制等非关键反馈；保存、提交、邀请和停用的最终结果保留在页面。提交时禁用重复点击，使用按钮附近 CircularProgress。

## Pages & Navigation

默认 / 重定向 /projects。全部业务页面要求有效会话；演示默认以成员进入，显示演示标记，可在独立控制面板切换管理员。/login 和 /accept-invite/:token 为公共演示页，不模拟已完成真实身份认证。失效链接、会话过期、403 和 404 有明确返回路径。登录后的 returnTo 只允许站内路径。

### Project 与工作列表

Project 关联业务系统中的一个大任务对象，可包含多个 Execution；不要求业务系统也将该对象称为 Project。Project 不复制权威业务状态，不承担结果合并或自动调度。

项目列表顶部 h5 与用途说明、搜索/来源筛选，下方单个 Paper 表格：项目名、来源及稳定业务引用、可见执行数、需我处理数、最近活动。项目工作区使用 Breadcrumbs、标题、业务引用、返回业务系统 outlined 按钮；统计为紧凑文字，下方执行/待决 Tabs。无结果允许清除筛选，无任务说明执行主要来自业务系统 API，不增加新建任务按钮。

全部执行表格展示 Project、目标、当前工作、归属人、待决数、最近更新。待决表格展示问题、Project、来源执行、类型、受影响范围、等待时间。标题 Link 导航；点击待决数定位首个请求。返回保留筛选和滚动，Project 切换清除不匹配的 Request/证据上下文。

│ 执行情况                │ 待决事项 [数量]            │

左侧进展默认仅关键事件；结果区分已确认、草稿和效果未知；执行记录可进入完整 Trajectory。顶部摘要不得把 Agent 计划或工具发起当成权威回执。

右侧紧凑请求列表使用 ListItemButton selected，选中后展示 Brief。问题、触发原因、受影响和可继续工作在首屏；Agent 建议用 info Alert 且不预选答案；事实、假设、缺口分开；证据 Link 提供来源与版本；关联模型折叠。无待决仍可查看已处理记录。

任务唯一归属人，不实现抢占、独立分派、多人并发处理或他人覆盖场景。Project 的负责人规则仍为 TBD，不能从任务归属推断。管理员不因角色取得他人的专业判断权或业务审批权。

### OM 浏览

列表列出名称、仓库、当前已索引 Commit、最近成功索引、缺口数、同步状态。成员只能看有权访问的 OM；管理员配置连接不等于所有成员获得仓库权限。

详情顶部明确当前查看 SHA 与最后索引时间。由执行进入时固定到该次执行使用的 Commit；切换修订只影响浏览，不改变执行依据。Tabs：概览、Decisions、关系与缺口、验证、关联实践。

* 概览只读展示 Root 的范围、路由与领域能力依赖。
* Decision 表格支持问题/适用条件搜索，进入详情展示 Question、Trigger/Applicability、Context Dependencies、Judgment、Outcomes、Precedents、Knowledge Gaps、Validation，以及实际存在的可选 Section。
* 关系先用可访问的关联列表与来源文件定位表达，不自建复杂图谱编辑器。解析不完整时提示，不猜测关系。
* 缺口区分 OM 中明确记录的知识缺口与学习分析提出的候选缺口；当前业务资料不足不能自动变成知识缺口。
* 验证记录展示场景、方法、版本、结果、证据与限制；区分静态检查、推演、模拟和受控运行，不以结构正确宣称成熟。
* 所有页提供在 Git 查看文件/修订入口，无内置编辑、Review、批准、合并。原型用明确标识的 Git 演示详情代替无效外链。

### Trajectory 与 Decision Episode

Trajectory 为执行的授权证据视图，而非通用聊天日志或隐藏思考链。顶部标明执行、OM/Runtime/Skill 版本、记录覆盖时间与缺失提示。支持事件类型、时间范围、Decision 过滤，分页加载，不自动跳动打断阅读。

事件列为时间、类型、摘要、关联判断、结果确认程度；点开 Drawer 查看工具输入/输出的经脱敏可见部分、权威回执、来源版本、前后关联。敏感字段、不可访问记录、已按政策清理的数据均有占位说明，不泄漏内容。

从事件进入 Episode：展示问题、当时 Context、知识版本、结论、人工干预、后续反馈及证据限制。Episode 不是已采纳 Precedent。选择一组事件可预览候选片段，保存为分析引用是本文交互提案；不能修改原始 Trajectory。

### 学习中心与外部协作

学习中心用 Tabs 区分分析记录、学习发现、改进候选。筛选来源 Project/Execution、OM、归因目标与审阅标签；统计仅反映授权且实际有记录的样本，不直接显示领域失败率或虚构收益。

学习详情依次展示观察事实、相关证据、原有预期、原因解释与替代解释、Knowledge Delta、适用范围与不确定性、归因目标、建议与验证计划。目标可以是 OM、Context Routing、Skill、工具/Runtime 或其他责任，不强制转成 OM 规则。

人工反馈表单支持支持继续研究、需补证据、暂不采用并要求理由；这些只是审阅标签，不是权威知识发布。候选修订另展示基线 SHA、涉及 Decision、预期行为变化与验证材料。关联 PR/MR 后显示来源、最后同步、审核/合并事实；合并不自动代表当前执行已采用新版本。

外部协作入口为“准备外部分析上下文”：预览选定 Episode、版本和可见引用，检查敏感性与证据完整性，确认后生成演示上下文包。生产导出协议/有效期/权限复核 TBD；原型只下载脱敏虚构文本，绝不自动上传完整会话。可从外部手动提交演示发现或证据引用，注明来源环境、作者声明和缺失记录，不宣称已验证其真实性。

方法指南解释 OME 初版构造、实践改进与反思模块的按需组合，以及 Airic Work Skill 的执行职责。提供复制仓库引用、版本和方法说明，不内置外部 Agent 聊天或自动控制本地会话；具体安装命令未确认则标 TBD，不伪造。

### 系统设置

仅管理员访问，左侧二级 List，右侧最大约 960px 表单区。每节独立保存，变更后显示未保存标记；离开提示保存/放弃/取消。测试连接与保存明确分开，成功持久 Alert 含生效范围，不自动启动执行。

| 分区 | 字段与内容 | 交互及边界 |
| --- | --- | --- |
| 基本信息 | 组织显示名称、默认时区 | 单组织，不增加切换、租户或计费；名称不改业务标识 |
| Git 连接 | 托管类型、仓库 URL、凭据引用、默认浏览分支、同步记录 | 新增/编辑、只读连通测试、触发索引；分支不是执行版本；同步失败保留最后成功索引 |
| 业务连接 | 来源系统标识、显示名、业务跳转模板、MCP Endpoint、凭据引用 | 测试不做业务写入；标明可发现能力与授权范围；连接正常不等于每个任务有权使用 |
| API 接入 | 调用方标识、身份关联说明、可用产品操作与近期接入记录 | 属于业务连接子页；创建/查询/取消执行和查询/处理Request语义说明，字段/认证协议 TBD，不编造已发布端点或真实令牌 |
| Runtime 与 Skills | Pi Durable 目标、环境、已发布能力清单、版本、资源和访问边界说明；OME/执行Skill版本及验证记录 | 当前实际能力未验证的标未验证；原型只读环境配置，版本更新展示影响评估与回归要求，不实现热切换或任意system prompt编辑 |
| 数据与安全 | Trajectory/片段保留、敏感字段策略、导出限制的策略摘要与来源 | 原型只读，不预填未经确认的保留天数，不实现一键删除审计或全量导出 |
| 管理审计 | 邀请、角色修改、停用、连接变更和测试/索引结果 | 搜索与详情只读；记录操作者、时间、对象、操作结果、脱敏变更摘要，不显示秘密值 |

Git、业务MCP和公开API是三个方向，设置中不能混作一个“全能集成”。MCP是领域能力接入，不为 Airic Work 增加对外 MCP 服务。凭据使用引用或演示连接器，不向 localStorage 保存秘密。断开/禁用连接需显示依赖与运行中影响；影响无法确定则阻止操作并提示待实现检查，不通过设置静默停止任务或切换执行版本。

### 个人设置

页面含资料与偏好两区。资料：显示名可改，登录邮箱、组织和角色只读，头像使用首字母，不加入上传复杂度。偏好：简体中文/English (US)、IANA 时区、待决新增/执行异常/学习反馈三项站内通知偏好；各区显式保存与恢复已保存值。

默认简体中文；若英文未实现，选择后明确演示限制，不能假称全局已切换。时间按个人时区显示并保留原始时间信息。不增加深色主题或紧凑度自定义，以维持当前视觉规范。通知偏好只影响提示，不隐藏待决任务、不绕过权限。邮件、短信、浏览器推送不在本轮，站内通知用顶部图标与列表演示，点击回到有权访问的对象，已读与正式处理分开。

### 用户管理

单组织，角色只有管理员、成员。表格列姓名、邮箱、角色、账户状态、最近登录、操作；支持搜索、角色与状态过滤。状态标签邀请中、有效、已停用、邀请过期仅为管理展示提案。

* 邀请 Dialog：邮箱、角色、用途说明；校验格式、已有有效账户和待接受邀请，避免重复邀请。提交后显示邀请已登记；邮件未连接时明确未发送，仅允许复制带演示标记的邀请入口。
* 邀请中可撤销或重新生成入口，旧入口失效。接受页显示组织/邀请角色，模拟确认后变为有效；过期或撤销提示联系管理员，不自动复活。
* 角色更改需确认影响；不能停用或降级最后一个有效管理员。本轮不允许在管理页停用自身，避免自锁。
* 停用前展示是否仍为执行唯一归属人及待处理请求数量。存在未交接责任时阻止停用，提示需按后续设计的责任交接流程处理；本轮不新增转派机制。管理员不会自动接管决定。
* 停用不删除历史处理人、审计或执行轨迹；恢复需显式确认，不自动恢复外部业务授权。会话撤销和调用凭据联动在生产安全契约中另行实现，界面不能假报已完成。

## Core User Flows

### Flow 1：从业务大任务完成一次正式决定

1. 默认项目列表进入 P1，查看其多个执行；点击待决数或从业务系统深链进入执行 A 的指定 Request。
2. 左侧立即说明正在做、等待和可继续的部分；右侧首屏说明问题和影响，局部 Skeleton 后展示 Brief。
3. 点击证据打开临时 Drawer，查阅版本/定位和原文；无法访问时明确限制，摘要不替代核验。关闭恢复焦点和草稿。
4. 选择请求允许的处理方式。专业判断用无预选 RadioGroup+理由；补充事实要求来源；授权明确对象/动作/范围；调查要求具体问题。
5. 点击下一步，Dialog 复核请求、动作、理由、影响与业务审批/OM边界。最终按钮按动作命名，提交中阻止重复点击。
6. 服务确认后先显示处理已记录，再等待新的执行事件；实际反馈后才显示工作继续。调查请求记录不能被误报成原问题已解决。
7. Project、执行和跨项目队列读取同一记录；业务完成始终以业务系统为准。上下文过期保留草稿并要求复核，同一用户重复提交返回原记录，未知结果先查询。

首次价值：不用通读轨迹即可核验证据并完成可追溯判断。

询问入口只解释已有记录；输入同意/继续不会自动生成正式决定。取消在更多菜单中单独确认，先接受请求后确认实际停止，保留已有业务效果和未知调用，不影响同项目其他执行。离开窗口不影响后台。

### Flow 2：从执行证据到有限定的学习候选

1. 从执行记录进入 Trajectory，筛选关联 Decision，查看权威回执和人工干预，打开 Episode。
2. 点击分析实践，Dialog 预览 Episode、OM/Skill版本、证据覆盖与数据边界；选择本次分析范围并确认。此手动入口是本文提案，自动调度 TBD。
3. 原型显示分析请求已记录、模拟处理中、结果可查看，允许查询；失败保留输入，不能展示凭空分析结论。不自动执行业务写入、修改 OM 或运行完整 OME。
4. 进入学习发现，核对事实与替代解释，填写需补证据/继续研究/暂不采用及理由。
5. 如涉及 OM，可关联候选修订、验证材料与已有 PR/MR；在 Git 继续审核。只有 Git 同步事实才显示合并，不把人工支持视为权威采用。
6. 回到 OM 固定修订查看相关实践；保留原执行 SHA，不静默替换。

外部专家可改为准备脱敏上下文包，在自己选择的 Agent 中使用 OME 或执行Skill。平台只交付授权内容，不上传完整外部会话，也不建立持续上下级Agent关系。

### Flow 3：管理员完成最小接入准备

1. 管理员进入系统设置新增 Git 演示连接，填仓库与凭据引用，测试只读连接；成功仅代表连通。
2. 保存后显式触发索引，看到请求接受和完成分开，失败时保留旧索引；进入 OM 查看明确 Commit 和解析限制。
3. 配置示例业务来源与 MCP，测试显示授权能力概要，不执行业务写入。查看标准 API 的接入说明与身份关联限制。
4. 查看 Runtime/Skill 实际可见能力与版本；缺失领域依赖标为缺口，不能以OM规则文本掩盖。
5. 管理审计出现脱敏记录；既有执行不因设置保存切换知识版本、权限或Runtime。

### Flow 4：邀请成员并安全维护账户

## Flow 4：管理员创建与维护用户及业务身份

1. 管理员通过用户管理主按钮新增用户：填写显示名、唯一登录标识/邮箱、角色（管理员/成员）及初始状态（有效/已停用），校验格式与重复账号；创建立即生效，不需成员接受。账户已创建不等于业务身份已关联或业务授权已完成。凭据初始化、SSO 或管理员重置机制为 TBD，不假定默认密码或发送任何邀请链接。
2. 管理员在用户详情的“业务身份”页签建立或维护平台 userId 与外部系统的映射：source system/instance、externalSubjectId/业务用户ID、验证依据与状态。仅在业务系统可验证时映射生效；仅填引用显示为“待验证”。同一用户在同一业务系统实例仅允许一个有效映射；同一外部身份不能映射到多个平台用户（最小原型假设）。管理员不能代替用户完成本人同意、查看其令牌或使用管理员身份测试成员权限。
3. 成员在个人设置新增“业务账号”区：列出已关联系统、脱敏显示稳定ID、身份验证状态、授权状态、授权范围、到期信息（未知表示未知）、最近验证时间；允许成员查看、连接/重新授权与撤销自己的委托。撤销前显示受影响执行，确认后使后续依赖该委托的 MCP 操作失效，但不能回滚已发生的业务效果或改写历史。
4. 业务创建执行链路明确区分：API 调用方、实际发起用户、Execution 归属的业务用户、Agent 技术执行者与实际决策处理人。没有映射、委托或权限不得发起相应领域操作。MCP 的读取/写入按本人业务权限与任务范围校验；平台不使用共享服务账号或管理员账号代替用户操作。
5. 执行工作区顶部展示执行身份摘要：代表谁、业务账号、系统、当前授权可用性；详情 Drawer 显示调用方、技术执行者、实际发起人、授权范围与最近校验。失效时显示 warning Alert 并提示到个人设置重新授权，非本人仅只读提示。有效映射不等于拥有业务审批权限。
6. 管理员创建/停用用户仍保留最后有效管理员保护与防自锁规则；有未交接执行责任时阻止停用，历史记录不删除。审计记录包含操作者、操作、目标、时间、脱敏摘要、业务身份映射变更历史。
7. 演示数据集调整为：一个管理员、一个有 A 任务的成员（已关联业务身份）、一个无待交接任务的成员（可已关联或未关联）、一个已停用账户。移除邀请、接受邀请、撤销/过期邀请、邀请 token、Invitation 对象及 /accept-invite/:token 路由等所有相关功能与场景；公共页面仅保留 /login 演示页。

## Data Model & Backend

以下是原型展示模型，不是正式 Schema 或 API。业务系统和工作台共用执行/决策模拟服务，不能各自维护状态。管理与知识服务不通过任意状态编辑器修改运行时。

| 展示对象 | 原型需要的信息 | 关系 |
| --- | --- | --- |
| User | ID、显示名、邮箱、role、status、最近登录 | 个人偏好独立；role不是业务权限 |
| Invitation | 邮箱、目标角色、状态、演示入口引用 | 接受后关联User；失效不重用 |
| Project | ID、名称、来源、稳定业务对象引用、跳转引用 | 聚合多个Execution |
| Execution | ID、projectId、ownerId、目标/范围、OM SHA、Runtime/Skill版本、工作摘要、结果 | 原型一个Execution属于一个Project；跨项目迁移 TBD |
| Request/Resolution | Brief、允许动作、内容/业务版本、处理记录和接受结果 | 属于Execution；不能由聊天创建Resolution |
| EvidenceReference | 来源对象、版本、定位、可访问性、摘要/片段 | 原文权威仍在业务系统 |
| OMRevision/DecisionIndex | 仓库引用、SHA、Root、Decision索引、缺口/验证、解析限制 | 缓存视图，Git是权威 |
| TrajectoryEvent/Episode | 时间、动作/观察/回执、干预、关联版本、覆盖与敏感性 | 原始事件只读；Episode不是正式Precedent |
| AnalysisRecord | 输入范围、相关版本、运行反馈、输出引用、失败信息 | 分析入口提案，不等于业务任务重跑 |
| LearningFinding/Proposal | 观察、证据、解释、Delta、范围、归因、反馈、验证与PR引用 | 可合并展示，不要求独立生产表 |
| Connection/RuntimeInfo | 方向、Endpoint/仓库引用、秘密引用、测试结果、能力与版本 | 不在OM中硬编码具体凭据 |
| Preference/Notification | 用户、语言/时区、提示偏好、对象引用、已读 | 已读不等于已决定 |
| AuditRecord | 操作者、操作、目标、时间、结果、脱敏摘要 | 只读，不记录秘密 |

查询和数量只基于授权可见对象，不泄漏不可见内容或数量。管理员配置权限不扩展业务对象权限。唯一归属人模型不取消请求/业务版本有效性和幂等保护。

模拟服务支持查询/取消执行、查询/处理请求、查询后续、索引OM、读取轨迹、登记分析与反馈、关联PR、保存个人偏好、邀请/角色/启停、连接测试及配置保存。它们是服务动作说明，不定义 HTTP 路径、OAuth流或公开Schema。

创建执行仍通过业务系统标准 API 的演示场景说明，涵盖调用方、执行身份、实际处理人、目标/范围、OM依据、幂等和接受/执行分离；不把工作台变成主要发起入口。鉴权、异步变更通知、真实API密钥发行与轮换 TBD。

只将虚构数据写入 localStorage；草稿、已接受记录与设置分别保存，提供版本化演示数据和重置。真实凭据、PII、生产轨迹不进入原型。生产后台的恢复、审计、授权复核、记录保留和删除机制需要独立设计。

## Key Components

### Decision Brief、处理表单与确认

Brief 顺序：问题/动作 → 触发与影响 → 建议及不确定性 → 事实/假设/缺失 → 方案风险 → 证据 → 模型版本。无依据可展示无建议，不生成确定性结论填空。

表单采用 FormControl、RadioGroup、TextField outlined、FormHelperText，理由 multiline minRows 3。不用自制可点击卡替代标准控件。右侧 sticky 操作区背景 paper、divider、p2；唯一主按钮下一步：核对并提交。Dialog maxWidth sm，左返回修改、右正式提交，不添加无意义确认复选框。

### 证据与关联对象 Drawer

temporary Drawer 不成为第三常驻列；标题、对象与版本固定可辨，原文和摘要有独立标签。跨 Episode、OM 和发现复用同一证据组件。403、记录已清理、加载失败和缺少版本分别提示。关闭恢复焦点和原页面上下文，不覆盖草稿。

### OM 阅读器与版本选择器

只读渲染标题、列表、表格和代码，清理不安全HTML。版本 Autocomplete 显示短SHA与时间，正文保留完整SHA。缺失的知识 Section 标未提供，不自动补写。版本切换和Git同步从不触发执行热更新。

### Trajectory 与 Episode

MUI Table/List 分页、Accordion和详情Drawer组合；事件有稳定链接，过滤可恢复。保留原始确认程度，不展开隐式推理。选中片段的预览清楚显示范围和缺失记录；从 Episode 到学习与 OM 均可返回原上下文。

### 学习审阅与 Git 关联

观察、解释、建议视觉分区，不以单一绿色成功标签掩盖不确定性。审阅必须保留理由和历史；关联PR校验仓库/修订信息并标示最后同步；无法确认Git状态显示未知，手动填链接不等于审核或合并。新版本是否正式用于未来执行仍由后续契约决定。

### 设置表单、邀请与角色保护

设置表单统一脏值检测、保存、恢复与离开提示。测试、保存、实际生效分离；测试失败不清空输入。密钥字段仅演示引用，提交反馈不回显秘密。成员管理的Menu只显示可用动作，但所有模拟服务也校验权限，不能只隐藏按钮。

邀请与停用Dialog说明影响，防最后管理员自锁、有待交接责任则阻止操作；不新增转派流程。历史用户名可显示当前账户已停用，但原处理记录不可改成管理员。

### 空白与错误

| 场景 | 界面反馈 | 可用操作 |
| --- | --- | --- |
| 无待决 | 不需要你处理 | 查看进展/历史 |
| 非任务归属人或授权无效 | 只读与明确原因 | 不提供管理员绕过 |
| Context过期 | 显示变化，保留草稿 | 复核后重新确认 |
| 提交结果未知 | 不报确定成功/失败 | 查询同一记录 |

| 轨迹不完整 | 显示覆盖范围 | 保留证据限制 |

## AI Generation Notes

### 演示数据与实现顺序

所有名称、资料、仓库、版本与结论均标为虚构，不宣称是 CertLab 的实际规则。

1. 保留 P1 供应商材料合规评估，含 A 证据完整性检查、B 资料版本核对、C 检查摘要整理；P2 设备资料复核含 D 附件清单核对。A/B/D有独立工作，C Agent结束但业务完成未确认。每个执行仅一位归属人。
2. A 的请求为缺签署页的补充说明能否作为临时参考；两份版本化演示证据，相关Decision与固定OM SHA。处理后的后续事件与项目数量来自同一存储。
3. 添加一个OM，两个演示修订、三个Decision、关系引用、一项知识缺口；另有一次索引失败且可查看最后成功修订。
4. 添加一个Episode、一条OM相关发现、一条工具归因发现、一条证据不足发现；候选修订分别展示未关联与已有演示PR，Git合并与执行仍用旧SHA同时存在。
5. 添加一个管理员、一个有A任务的成员、一个无待交接任务的成员、一个待接受邀请。最后管理员/待决责任保护均可重复验证。
6. Git/MCP各一个演示连接、Runtime/Skill只读能力说明、审计记录、站内通知及个人偏好。

分两批迭代可操作原型：先补 OM/Trajectory/Episode/学习闭环，再补系统/个人/用户管理；每批都支持真实导航、筛选、返回、保存与异常演示。不用无内容菜单伪装完成能力。

### 可重复验证的状态

演示控制面板与正式UI分开：正常、Context更新、证据不可访问、提交未知、取消延迟、Git同步失败、轨迹缺失、分析失败、邀请失效与角色切换。不包括多人并发竞争。未知提交通过查询恢复同一处理结果；不能只关闭Alert。取消先记录接受，再用后续反馈确定实际结果。调查请求不立即触发已解决标记。

通知和分析使用明确标识的模拟延迟，不宣称邮件真实发送或后台实际运行。系统配置保存不自动创建业务执行、写业务状态、修改OM或扩大权限。

### 非目标与仍待确认

* 不重建Git治理、通用Agent聊天、业务专业UI/事务或对外MCP。
* 不新增任务转派、任意暂停/重跑、热切换OM/Runtime、自动合并或无人审核知识发布。
* Project跨项目共享/迁移、负责人继承、执行重试/组合与业务覆盖仍TBD。
* 自动反思时机、调度、数据交付协议、真实通知渠道和认证/秘密托管需要后续设计。
* 保留政策天数、指标目标、Skill安装地址和真实能力未明确则显示TBD或未验证，不虚构。

### 走查与验收
